## 目的

Hakutaku は、運用先の専用端末内に点在するログ、DICOM、データベースなどを、元データを変更せずに読み込み、調査・確認するための Windows 向け GUI ビューアです。本書は、製品全体の確定要件、初期リリースの境界、後続リリースへ送る範囲を定義します。

本書の状態は、この変更が `main` へマージされた時点で採用済みになります。詳細な機能は[機能要件](../requirements/functional.md)、品質条件は[品質要件](../requirements/quality.md)、実現境界は[アーキテクチャ概要](../architecture/overview.md)、データの扱いは[データ取り扱いとセキュリティ](../security/data-handling.md)を正本とします。

## 初期リリースの範囲

初期リリースの中心はテキストログビューアです。共通シェル、`hakutaku.yaml` の読み込み、設定にないローカルファイルを開くファイル選択 UI、可変形式・可変文字コードのログ、複数ログの時系列統合表示、選択範囲のクリップボードコピー、大容量ログ向けの段階読み込みを含みます。

技術・配布・動作環境・権限昇格・エラー処理・診断ログ・機密情報の要件は、初期リリースから適用します。実装と検証の順序は[ロードマップ](../roadmap.md)、初期リリースに含めない要件の一覧は後続バックログの [Issue #13](https://github.com/vyPeony/Hakutaku/issues/13) を参照します。

## 読み取り専用の意味

読み取り専用は製品の不変条件です。Hakutaku はログ・DICOM ファイルを変更せず、データベースの論理的内容とスキーマを変更しません。更新系 SQL、DDL、対象データの作成・更新・削除機能は提供しません。

SQLite の WAL モードを同時参照する場合は、SQLite ライブラリが管理する `-wal`、`-shm` の作成、アクセス、更新が発生し得ます。これは主 DB の論理的内容を変更しないことと区別します。ファイルシステム上の書き込みが一切発生しないことまでは保証しません。詳細は `DB-001`、`DB-006`、`DB-009`、`DB-012`～`014` と[データ取り扱いとセキュリティ](../security/data-handling.md)を参照します。

## 対象環境と運用

- 主たる対象は Windows 10 IoT Enterprise LTSC の64ビット版で、最古機種は version 1809 / build 17763 相当を想定します。Windows 11 と通常版 Windows 10 の64ビット版も対象です（`ENV-001`）。
- 主たる実行場所は運用先の専用端末そのものです。同じ端末で稼働する他の業務ソフトウェアが動作したまま、同一 PC 上のログや DB を調査する運用を標準ケースとします（`ENV-010`、`ENV-011`）。
- 開発用 PC でも同じ実行ファイルと同じ機能を使用します。別の端末のデータは、SCP などで事前にローカルへ取得してから開きます（`CFG-010`）。
- Evergreen WebView2 Runtime の導入状況は機種ごとに異なるため、OS 導入済み Evergreen と任意配置の Fixed Version の両経路を正式に保守します（`ENV-008`、`DIST-006`～`017`）。

## 暫定方針と検証待ち

次は確定要件ではなく、試作結果により変更できる設計方針です。

- 共通シェルと形式別ビューアの分離構成は、[アーキテクチャ概要](../architecture/overview.md#暫定構成)の暫定構成を正本とする。
- 大量データの読み込み方式は、[機能要件](../requirements/functional.md#暫定設計と受け入れ確認)の該当項目を正本とする。
- 読み込みと解析を UI スレッドから分離し、進捗表示とキャンセルを可能にする。
- Rust + Tauri 2系は暫定採用であり、段階1の LTSC 実機検証が完了するまで確定しない（`TECH-003`、`VER-001`）。
- DICOM プライベートタグ解析スキーマは仮案 v1 であり、実データによる試作で改訂できる。
- フロントエンド保持上限の初期値は段階0（P04-3）の実測で 10,000 行に決定済み。WebView2 の追加メモリ目安と対象端末上の資源抑制の既定値、および保持上限見直しの要否は、段階1（P13）の実測で確定する。
