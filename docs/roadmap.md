## 目的

ロードマップは期日の約束や作業状態の正本ではなく、版1.10の確定要件を満たすために不確実性を減らす順序を示します。本書の状態は、この変更が `main` へマージされた時点で採用済みになります。

各タスクの目的、受け入れ条件、担当者、進捗は GitHub Issue / PR を正本とします。段階1（P13）の検証項目は [Issue #12](https://github.com/vyPeony/Hakutaku/issues/12)、初期リリース後（P14）の対象と除外要件の一覧は [Issue #13](https://github.com/vyPeony/Hakutaku/issues/13) が引き継いでいます。

## 実装着手前の前提（達成済み）

次の前提は、段階0の着手前に満たしました。

1. 初期仕様 版 1.10 を `docs/` の正本へ取り込み、対象文書を採用済み（`Accepted`）にした
2. Rust + Tauri 2系の暫定採用を [ADR-0001](architecture/decisions/0001-rust-tauri-provisional-adoption.md)（`DEC-002` 対応）に記録した
3. P00 の対象範囲、受け入れ条件、担当範囲を合意した

## 段階0 — 現行開発環境での実装と先行検証

### 段階0の完了ゲート

- 起動、日本語表示、ファイル選択、ログ読み込み、時系列統合、仮想スクロール、ヒープ会計、クリップボードコピーが成立している。
- Evergreen と Fixed Version の両 Runtime 経路、Runtime 未検出、`WebView2` 書き込み不可の経路が検証されている。
- Rust コアのヒープ会計、フロントエンド保持上限、連続スクロール時のメモリ計測手段が機能している。
- 参照内容をネットワークへ送信せず、参照元を変更せず、実行時の書き込み先が規定領域に限られることを観測している。
- 検索・絞り込み、SQLite、DICOM、索引キャッシュ、DICOM 匿名化・マスキング・監査ログ、ドラッグ＆ドロップが初期リリースに存在しないことを確認している。
- 段階1で残る確認が、LTSC 固有の要因と他の業務ソフトウェアとの同時稼働の実測に絞られている。

## 段階1 — LTSC 実機検証と技術選定の確定

| フェーズ | 目的 | 主な要件 |
| --- | --- | --- |
| P13 | Windows 10 IoT Enterprise LTSC 実機での最終検証と `TECH-003` の確定判断 | `VER-006`、`PERF-015`、`ENV-001`、`LOG-027` |

P13 では、最古機種のビルド番号、Evergreen 未導入環境での Fixed Version 起動、Runtime フォルダ ACL の要否、他の業務ソフトウェアの稼働中における対象ログ全種の読み取り、同じく稼働中の性能、資源抑制の既定値を実測します。合格した場合に Rust + Tauri 2系を確定し、満たさない場合は新しい ADR で再選定します（`TECH-003`、`VER-001`、`VER-006`）。

## 全段階で維持する条件

- 参照データを変更せず、編集機能を持たない（`PROD-003`、`ERR-003`）。
- 参照内容をネットワークへ送信しない（`SEC-001`）。
- 高速性を重視し、対象端末上では他の業務ソフトウェアへの影響回避を優先する（`PROD-008`、`TECH-001`、`PERF-003`、`ENV-011`）。
- GUI 層と Rust コア層の境界を保ち、段階1での技術再選定に備える。
- 実行時の書き込み先を `logs`、`temp`、`WebView2` に限定する（`SEC-009`）。
- 暫定設計を確定要件へ昇格させず、検証結果により変更する場合は ADR と関連正本を更新する。
