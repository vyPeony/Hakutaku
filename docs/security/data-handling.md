# データ取り扱いとセキュリティ

- 状態: 採用済み（Accepted）
- 管理責任者: 未定（TBD）
- 最終更新日: 2026-08-01
- 要件の基準: Hakutaku 初期仕様 版 1.10

## 目的

本書は、Hakutaku が扱う参照データ、機密データ等、診断ログ、クリップボード、キャッシュ、一時ファイル、WebView2 データの保存・通信・削除境界を定義します。本書の状態は、この変更が `main` へマージされた時点で採用済みになります。

Hakutaku は運用先の専用端末の管理されたローカル環境で使う開発・調査ツールです。DICOM タグ、端末上のログ、DB、ファイル名・パスには、個人を識別し得る情報その他の機密情報（以下「機密データ等」）が含まれ得ます。版1.10は診断性を優先し、診断ログへの実値記録を許容します。マスキング、暗号化、アクセス制御を Hakutaku の機能要件とはせず、導入フォルダと端末の管理を利用者または導入組織の責任範囲とします。

## 不変条件

- 参照内容をネットワークへ送信しません（`SEC-001`）。更新確認、遠隔測定、クラッシュ送信、自動ダウンロードも行いません。
- ログ・DICOM ファイルを変更せず、SQLite の論理的内容とスキーマを変更しません。SQLite WAL の付随ファイルは `DB-012`～`014` の例外に従います。
- 実行時の書き込み先を実行ファイル直下の `logs`、`temp`、`WebView2` に限定します。後続でキャッシュを提供する場合だけ `cache` を追加します（`SEC-009`）。Fixed Version Runtime の ACL 操作は `DIST-010` が明示する `WebView2Runtime` フォルダだけの例外です。
- クリップボードへの複製は利用者の明示操作時だけ行います（`COPY-006`、`SEC-004`）。
- リリースビルドでは WebView2 の開発者ツールを無効化し、CSP と最小 Capability でフロントエンドの通信・任意ファイルアクセスを制限します（`SEC-011`、`SEC-012`）。

## 診断ログの確定要件

| ID | 要件 |
| --- | --- |
| DIAG-001 | 診断ログは、実行ファイルが存在するフォルダの直下に `logs` フォルダを作成し、その中へ保存する。ほかの場所へは保存しない。 |
| DIAG-002 | 既定のローテーションは1ファイル 10 MiB、5世代とし、設定で変更できること。 |
| DIAG-003 | 診断に必要な場合は、ログ本文、DB セル値、DICOM タグ値、DICOM 画素、認証情報、クリップボード内容その他の実値を診断ログへ出力してよい。機密性を理由とするマスキング、省略、伏字を必須としない。 |
| DIAG-004 | 参照元のフルパスや各種実値を、追加設定や警告なしで診断ログへ出力してよい。セッション内のソース ID と併記してもよい。 |
| DIAG-005 | 診断ログには時刻、重要度、モジュール、操作種別、ソース ID、エラーコード、スタックまたは内部位置を記録できること。 |
| DIAG-006 | 起動時または最初のログ出力時に `logs` フォルダがなければ作成する。作成または書き込みに失敗した場合は理由をユーザーへ通知し、別の保存先へ自動フォールバックせず、診断ログなしでアプリの動作を継続する。 |
| DIAG-007 | `PRIV-002` の昇格プロセスが出力した診断ログは、以後の非昇格プロセスから書き込みやローテーションができない場合がある。その場合も `DIAG-006` に従い、通知したうえで診断ログなしで動作を継続する。昇格プロセスの出力であることがログ内容から判別できること。 |

### 実装で確定した具体値（P01）

次は、P01（起動ブートストラップと WebView2 経路）の実装で確定した具体値です。**上表の要件（`DIAG-001`〜`007`）を変更するものではなく**、その具体化を記録するものです。

- 診断ログのファイル名は `logs/hakutaku.log` です。ローテーション時は `hakutaku.1.log`、`hakutaku.2.log`…の順に退避します。
- `DIAG-002` の既定「5世代」は、**現行ファイル（`hakutaku.log`）を含む合計5ファイル（最大50 MiB）**という意味で実装しています。退避のたびに世代番号を1つずつ繰り下げ、保持上限（既定5）を超える最も古い世代は削除します。
- 診断ログファイルの冒頭には、実値をマスキングしない方針と、`logs` フォルダの閲覧制限・持ち出し・保管・削除が利用者・導入組織の責任範囲であること（`SEC-005`）を明記した見出しを出力します。新規作成時とローテーション後の新しいファイルの両方で出力します。
- 各レコードには、出力したプロセスの権限を `proc=elevated`（昇格）／`proc=normal`（非昇格）／`proc=unknown`（判定不能）として記録します（`DIAG-007`）。診断ログは追記モードで開くため、昇格・非昇格プロセスのレコードが同一ファイルに混在し得ます。
- `code=` へ記録するアプリ内エラーコード（例: `HKT-W2-0007`）の書式と採番規則は、[エラーコード体系](../development/error-codes.md)を正本とします。

## 機密情報の確定要件

| ID | 要件 |
| --- | --- |
| SEC-001 | Hakutaku から参照内容をネットワークへ送信しない。オフライン動作要件 `PROD-014` を維持する。 |
| SEC-002 | 索引キャッシュは初期リリースでは提供しない（`CFG-011`）。後続リリースで提供する場合は既定 OFF とし、保存内容と保存形式に制約は設けず、暗号化およびアクセス制御は要件としない（`CFG-012`）。ON にする判断と保存先端末の管理は導入組織の責任範囲とする。 |
| SEC-003 | 後続リリースでキャッシュを提供する場合、削除は利用者による手動操作のみとする。自動削除・保持期限は設けない。GUI からキャッシュを消去できる機能は望ましい要件とする。 |
| SEC-004 | クリップボードコピーはユーザーが明示的に実行した場合だけ行う。機密データ等が他アプリへ渡り得ることを DICOM ビューアで初回コピー時に通知する部分は、DICOM ビューアを提供する後続リリースで適用する。初期リリースでは「明示的な操作時のみコピーする」ことだけを適用範囲とする。 |
| SEC-005 | 診断ログには機密データ等、認証情報、フルパスその他の実値が平文で含まれ得る。マスキング、暗号化、アクセス制御を Hakutaku の要件とせず、`logs` フォルダの閲覧制限、持ち出し、保管、削除は利用者または導入組織の責任範囲とする。 |
| SEC-006 | 一時ファイルが必要な場合は、実行ファイルと同じフォルダ直下の `temp` 配下に限定し、正常終了時に削除し、次回起動時にも残存ファイルを清掃する。 |
| SEC-007 | 初期リリースでは DICOM 匿名化、機密データのマスキング表示、操作監査ログを提供しない。利用可否と端末管理は導入組織の責任範囲とする。 |
| SEC-008 | 後続リリースでキャッシュを提供する場合も、暗号化、アクセス制御、保持期限、自動削除は行わない（`Q-029` 回答済み、`DEC-028`）。 |
| SEC-009 | Hakutaku が実行時に作成・書き込みするフォルダは、実行ファイルと同じフォルダ直下の `logs`、`temp`、`WebView2`（および後続リリースでキャッシュを追加した場合の `cache`）に限定する。`%LOCALAPPDATA%` などユーザープロファイル配下へは書き込まない。導入フォルダごと退避・削除すれば、Hakutaku が残したデータをすべて処分できる状態を保つ。 |
| SEC-010 | `WebView2` フォルダには、WebView2 が保持する描画・実行状態が残り得る。内容は機密データ等を含み得るものとして扱い、`logs` と同じく、閲覧制限、持ち出し、保管、削除は利用者または導入組織の責任範囲とする。Hakutaku 側で暗号化やアクセス制御は行わない。 |
| SEC-011 | リリースビルドでは WebView2 の開発者ツールを無効化する。コンテンツセキュリティポリシーを設定し、ローカルの同梱リソース以外へのナビゲーションおよびリモートオリジンへの通信を禁止する。 |
| SEC-012 | Tauri の Capability は必要最小限に限定し、フロントエンドへ任意パスのファイルシステムアクセス権を与えない。ファイル・フォルダの読み取りは Rust コア側のコマンド経由に限定する。 |

## データ領域と責任

| 領域 | 初期リリース | 扱い |
| --- | --- | --- |
| `hakutaku.yaml` | 使用する | 実行ファイル直下の固定名。DB 認証情報は保存しない（`CFG-013`）。アプリは自動生成・上書きしない。 |
| `logs` | 使用する | 機密データ等、認証情報、フルパス、実値を平文で含み得る。10 MiB × 5世代が既定。管理は利用者・導入組織の責任。 |
| `temp` | 必要時だけ使用する | 正常終了時と次回起動時に清掃する。参照元とは別の一時領域であり、参照元を変更しない。 |
| `WebView2` | 使用する | WebView2 のユーザーデータ。機密データ等を含み得る。作成不能時は別領域へフォールバックせず、起動を中止する。 |
| `WebView2Runtime` | 条件付きで使用する | Fixed Version Runtime の配置先。利用者が任意追加パッケージを展開する領域で、Hakutaku の利用者データ領域ではない。`DIST-010` の条件で ACL を操作し得る。 |
| `cache` | 初期リリースでは存在させない | 後続で追加する場合は既定 OFF、平文・無期限・手動削除とし、対象ファイルの指紋照合を必須にする。 |

`logs`、`temp`、`WebView2`、後続の `cache` を含め、Hakutaku が残すデータは導入フォルダごと退避・削除できる状態を保ちます。OS バックアップ、クリップボード、利用者が持ち出した診断ログは Hakutaku の削除範囲外です。

## ネットワークと WebView2

- 起動・利用時に Runtime、更新、設定、遠隔コンテンツをネットワークから取得しません。
- WebView2 Runtime は OS 導入済み Evergreen または実行ファイル直下の Fixed Version を使用します。どちらもなければネイティブダイアログで通知して終了します。
- CSP でリモートオリジンへの通信とナビゲーションを禁止します。これは WebView2 側の防御であり、`SEC-001` は Rust コアと依存クレートを含むプロセス単位の送信監視でも検証します。
- ローカルの同梱リソースだけを読み込み、外部参照、マクロ、スクリプト、埋め込み内容を自動実行しません。

## ファイルとパーサー

- パス、ファイル名、ファイル内容、設定、DICOM バイナリ、DB 値を信頼できない入力として扱います。
- 読み取り範囲、配列長、再帰、ファイル数、深さ、処理時間、メモリ確保に上限を設けます（`ERR-004`、`DCM-018`～`020`、`PERF-*`）。
- ログの削除・縮小・置換、書き込み途中の末尾断片、共有違反を区別し、ロック解除や無断コピーで迂回しません（`LOG-023`、`LOG-026`、`LOG-027`）。
- DICOM の未対応転送構文と破損を区別し、画素データはデコードせず安全に読み飛ばします（`DCM-TS-*`）。
- SQLite は `mode=ro` 相当の読み取り専用接続を使い、WAL の整合性・ロック規則を回避しません。使用中 DB に `immutable=1` を自動適用しません（`DB-001`、`DB-009`、`DB-012`～`014`）。

## クリップボード

- コピーは `Ctrl+C` など利用者の明示操作時だけ行い、バックグラウンドで自動生成しません。
- 上限は UTF-8 換算 16 MiB または10万行で、超過時は部分コピーせず全体を拒否します（`COPY-004`、`COPY-005`）。
- クリップボードは Hakutaku の管理外への複製です。DICOM 提供時は初回コピーで機密データ等の可能性を通知します（`SEC-004`）。
- ファイルエクスポートは初期リリースの機能ではありません。

## 検証

- Hakutaku プロセスの送信を監視し、参照内容、診断情報、更新確認、遠隔測定がネットワークへ送られないことを確認する。
- ファイルシステム監視で、実行時の書き込みが `logs`、`temp`、`WebView2` と `DIST-010` の明示的な ACL 対象に限られることを確認する。
- 診断ログにフルパスと実値を記録できること、書き込み不能時は通知後も閲覧機能が継続し、別保存先へフォールバックしないことを確認する。
- 正常終了と強制終了後に参照元が変化せず、次回起動時に `temp` の残存物が清掃されることを確認する。
- リリースビルドで開発者ツールが無効で、CSP と Capability が `SEC-011`、`SEC-012` を満たすことを確認する。

## インシデント報告

脆弱性やデータ漏えいの可能性を見つけた場合は、[セキュリティポリシー](../../.github/SECURITY.md) の非公開経路を使用します。公開 Issue、Discussion、PR、診断ログの共有先へ、脆弱性の詳細、認証情報、実データ、個人情報を投稿しません。
