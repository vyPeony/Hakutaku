# エラーコード一覧（導入担当者向け）

- 状態: 採用済み（Accepted）
- 管理責任者: リポジトリメンテナー
- 最終更新日: 2026-08-19

## 目的

Hakutaku は、起動できない・処理を継続できないなどの一部の失敗に、`HKT-` から始まるアプリ内エラーコードを割り当て、診断ログへ記録します。本書は、Hakutaku を対象端末へ導入する担当者・導入組織（以下「導入担当者」）が、Hakutaku のソースコードを読まなくても、診断ログに記録されたエラーコードから原因と対処へたどれるようにするための一覧表です。

エラーコード体系そのものの正本（書式、領域の割り当て、採番手順）は[エラーコード体系](../development/error-codes.md)です。本書はその体系にもとづく、個別コードの意味と対処だけを扱う利用者向け文書であり、体系の規則自体は複製しません。

## エラーコードとは何か

- `HKT-<領域>-<番号>` という形式の識別子です（例: `HKT-W2-0007`）。`<領域>` はコードを割り当てたモジュールの区分、`<番号>` は領域内の4桁連番です。
- 接頭辞 `HKT-` は、Windows などが返す「OS エラーコード」（ダイアログの本文に数値で表示されることがあります）と区別するための固定接頭辞です。両者は別の体系であり、混同しないでください。OS エラーコードが表示された場合は、その数値自体は Windows 側のエラーであり、本書の一覧には含まれません。
- 現在割り当てられている領域は次の4つです。

| 領域 | 対象 |
| --- | --- |
| `W2` | WebView2 Runtime の検出、版判定、ACL、経路解決（起動ブートストラップ） |
| `CFG` | 設定ファイル `hakutaku.yaml` の読み込みと起動時検証 |
| `ENC` | 対象ファイルの文字コードの判定とデコード |
| `MEM` | メモリ予算と予約（`memory.budget_mib`） |

## 診断ログのどこに現れるか

エラーコードは、診断ログ（実行ファイルと同じフォルダの `logs\hakutaku.log`）の各レコードにある `code=` 欄に記録されます。診断ログの記録項目全般（時刻、重要度、モジュール、操作種別、本文、内部位置など）は[データ取り扱いとセキュリティ](../security/data-handling.md)の診断ログの要件（`DIAG-005`）を参照してください。

**現在の起動ブートストラップのダイアログ（Windows 標準のメッセージボックス）は、アプリ内エラーコードを表示しません。** 画面には状況の説明と対処方法だけが表示されます。エラーコードで状況を照合したい場合は、診断ログの `code=` 欄を確認し、本書の一覧表と突き合わせてください（ダイアログへコードを併記するかどうかは未決事項です。[エラーコード体系の未決事項](../development/error-codes.md#未決事項)を参照）。

## すべてのエラーにコードがあるわけではない

エラーコードは、次のいずれかに当てはまる失敗にだけ割り当てられます。

- 起動できない、または処理を継続できない失敗
- 利用者または導入組織側の対処が必要な失敗
- 手順書、FAQ、問い合わせ対応から参照される見込みのある失敗

該当しない失敗は、診断ログに `code=-`（ハイフン）と記録され、コードを持ちません。この場合も、診断ログの本文と内部位置（`at=`）から原因調査は可能です。本書の一覧表に載っていないコードは存在しないか、本書がまだ追随できていない可能性があります。後者の場合は[エラーコード体系](../development/error-codes.md)の採番台帳（各領域のモジュール）が正本です。

## W2: WebView2 Runtime のエラーコード一覧

WebView2 Runtime の検出・準備（起動ブートストラップ）で発生する8件です。Runtime の配置手順そのものは[WebView2 Runtime 導入手順書](./webview2-runtime-installation.md)を参照してください。

| コード | 意味（いつ起きるか） | 対処 | 関連要件 ID |
| --- | --- | --- | --- |
| `HKT-W2-0001` | 設定ファイル `hakutaku.yaml` の `webview2.force_fixed_version_runtime` を起動時に先行読み込みしたが、値を確定できなかった（構文エラー、値の型が真偽値でない、など）。起動は中止せず、既定値（自動判定）で続行する。 | 通常は緊急の対応不要です（既定値で起動は継続します）。設定ファイルの `webview2.force_fixed_version_runtime` が `true` または `false` の真偽値で正しく記述されているか見直してください。書式は[WebView2 Runtime の解決経路と開発環境での扱い](../development/webview2-runtime.md)の設定キーの節を参照。 | `DIST-017`、`CFG-023` |
| `HKT-W2-0002` | 導入済みの Evergreen WebView2 Runtime を検出できたが、その版が最低要求版（`86.0.616.0`）未満だった。この後、実行ファイル直下の `WebView2Runtime`（Fixed Version）の確認へ進む。 | 通常は対応不要です（Evergreen Runtime は自動更新されるため、実運用でこの下限を下回ることはまれです）。継続する場合は Windows Update や Microsoft Edge の更新を確認し、Evergreen WebView2 Runtime を最新化してください。更新できない場合は[導入手順書](./webview2-runtime-installation.md)の形態Bに従い Fixed Version Runtime を配置する方法もあります。 | `DIST-006` |
| `HKT-W2-0003` | Evergreen Runtime が既に使用できない（または `webview2.force_fixed_version_runtime` により検出自体をスキップしている）状態で、実行ファイル直下の `WebView2Runtime` フォルダを確認したが、Fixed Version Runtime が見つからなかった（フォルダが無い、`msedgewebview2.exe` がフォルダ直下にない、など）。この時点で両方の経路が使用できないため、起動は中止され、`HKT-W2-0007` としてもあわせて記録される。 | [導入手順書](./webview2-runtime-installation.md)の「手順2: 配布物を展開する」形態Bに従い、Runtime 追加パッケージを取得して `WebView2Runtime` フォルダを実行ファイルと同じフォルダの直下へ「平坦化」して配置してください。あるいは、対象端末へ Evergreen WebView2 Runtime を導入する方法もあります（手順1）。 | `DIST-006` |
| `HKT-W2-0004` | Evergreen Runtime が既に使用できない状態で、`WebView2Runtime` フォルダに Fixed Version Runtime は見つかったが、その版が最低要求版（`86.0.616.0`）未満だった。想定される配布物の版（現在 `150.0.4078.105`）とは異なる、古いまたは破損した Runtime が配置されている状態。この時点で両方の経路が使用できないため、起動は中止され、`HKT-W2-0007` としてもあわせて記録される。 | 配布担当者から対象版の Runtime 追加パッケージを再入手し、`WebView2Runtime` フォルダの中身一式を丸ごと置き換えてください（差分だけの上書きはできません）。詳細は[導入手順書](./webview2-runtime-installation.md#runtime-の版について)の「Runtime の版について」を参照してください。 | `DIST-006`、`DIST-011` |
| `HKT-W2-0005` | `WebView2Runtime` フォルダに対する App Container 用アクセス許可（ACL）の要否を判定できなかった。起動は中止せず、安全側に倒して Runtime の使用を続行する。 | 通常は対応不要です（起動は継続します）。この状態が繰り返し発生する場合、または後続で `HKT-W2-0006` に至る場合は、`HKT-W2-0006` の対処に従ってください。 | `DIST-010` |
| `HKT-W2-0006` | Evergreen Runtime が既に使用できない状態で、`WebView2Runtime` フォルダへ App Container（`ALL APPLICATION PACKAGES`）用の読み取り + 実行のアクセス許可を付与しようとしたが、現在の実行権限では設定できなかった（Windows 10 環境で起こり得る）。この時点で Fixed Version Runtime も使用不可として扱われるため、起動は中止され、`HKT-W2-0007` としてもあわせて記録される。 | エクスプローラーで `WebView2Runtime` フォルダを右クリックし、「プロパティ」→「セキュリティ」タブ→「編集」または「詳細設定」からアクセス許可を追加するか、管理者権限で Hakutaku を再起動して自動設定を再試行してください（フォルダの所有者、または管理者権限を持つ利用者が操作する必要があります）。この操作はフォルダのアクセス許可（メタデータ）だけの変更であり、Runtime ファイルの内容は変更されません。 | `DIST-010` |
| `HKT-W2-0007` | 導入済み Evergreen Runtime と、実行ファイル直下の Fixed Version Runtime のどちらも使用できず、Hakutaku を起動できなかった（起動を中止する終端のエラー）。画面には Windows 標準のメッセージボックスで、検出結果、配置先の絶対パス、対処方法が表示される。ACL 拒否（`HKT-W2-0006`）が原因の場合は、その内容を伝えるダイアログが先に表示される。 | 表示されたダイアログの案内、または[導入手順書](./webview2-runtime-installation.md)の「手順2: 配布物を展開する」形態Bに従い、Fixed Version Runtime を配置するか、Evergreen WebView2 Runtime を導入したうえで Hakutaku を再起動してください。Hakutaku は Runtime をネットワークから自動取得しないため、いずれかの方法での手動配置・導入が必要です。 | `DIST-009` |
| `HKT-W2-0008` | Evergreen Runtime が既に使用できない状態で、`WebView2Runtime` フォルダの DACL に、App Container（`ALL APPLICATION PACKAGES`）に対する拒否 ACE があり、それが読み取り + 実行のアクセス権と重なっていた。Windows は DACL を先頭から評価し拒否を許可より優先するため、許可 ACE を追加しても有効にならない。そのため許可 ACE の追加は行わず、Fixed Version Runtime も使用不可として扱われるため、起動は中止され、`HKT-W2-0007` としてもあわせて記録される。 | `WebView2Runtime` フォルダの所有者、または管理者権限を持つ利用者が、エクスプローラーで対象フォルダを右クリックし、「プロパティ」→「セキュリティ」タブ→「詳細設定」から、`ALL APPLICATION PACKAGES`（または関連するグループ）に対する**拒否**エントリの内容を確認し、読み取り・実行を妨げている場合は見直してください。管理者権限での再起動だけでは解決しません（拒否は許可より優先されるため、権限を上げても許可 ACE の追加自体が無効化されます）。この操作はフォルダのアクセス許可（メタデータ）だけの変更であり、Runtime ファイルの内容は変更されません。 | `DIST-010` |

## CFG: 設定ファイルのエラーコード一覧

実行ファイルと同じフォルダの設定ファイル `hakutaku.yaml`（`CFG-014`）の読み込み・起動時検証で発生する1件です。

| コード | 意味（いつ起きるか） | 対処 | 関連要件 ID |
| --- | --- | --- | --- |
| `HKT-CFG-0001` | `hakutaku.yaml` は存在するが、構文または値が不正で起動時検証に失敗した（安全モード起動）。Hakutaku は誤った設定を黙って既定値へ置き換えず、設定由来のデータソース・ログ解析プロファイル・キャッシュをすべて無効にした状態で起動する。この行に続けて、検証エラーが1件ずつ（ファイル名・行・列・項目・理由）記録される。 | 診断ログに続けて記録された各エラーの行・列・理由に従って `hakutaku.yaml` を修正し、Hakutaku を再起動してください。設定ファイルが存在しない場合（既定値起動）はこのコードになりません。 | `CFG-016` |

## ENC: 文字コードのエラーコード一覧

対象ファイルを開くときの文字コード判定・デコードで発生する2件です。

**この2件は、現時点では診断ログの `code=` 欄へ記録されません。** 対象を開けなかった旨と理由は診断ログの本文（`ENC-006` などを含む日本語の説明）と画面のエラー表示に出ます。`code=` 欄への記録は後続の変更で対応します。

| コード | 意味（いつ起きるか） | 対処 | 関連要件 ID |
| --- | --- | --- | --- |
| `HKT-ENC-0001` | 開こうとしたファイルの先頭に UTF-16 LE/BE の BOM があり、未対応の文字コードと判定した。初期リリースは UTF-16 に対応しないため、そのファイルの読み込みは中止される（アプリは動作を継続する）。 | 対象ファイルを UTF-8 または対象端末の ANSI コードページへ変換してから開いてください。ログの生成元の設定で出力文字コードを変更できる場合は、そちらの見直しを推奨します。 | `ENC-006` |
| `HKT-ENC-0002` | ログ解析プロファイルが指定した Windows コードページが対象端末に存在せず、デコードできなかった。そのファイルの読み込みは中止される（アプリは動作を継続する）。 | `hakutaku.yaml` の該当プロファイルの `ansi_codepage` の番号を見直すか、対象端末へ該当する言語パックを導入してください。起動時に検出できた場合は、この前に安全モード（`HKT-CFG-0001`）として一括で報告されます。 | `ENC-007` |

## MEM: メモリ予算のエラーコード一覧

メモリ予算（`hakutaku.yaml` の `memory.budget_mib`）に対する予約判定で発生する1件です。

| コード | 意味（いつ起きるか） | 対処 | 関連要件 ID |
| --- | --- | --- | --- |
| `HKT-MEM-0001` | 読み込みや索引作成の前に行うメモリ予約が、予算の上限に達したため拒否された。要求量・確保済み量・予約済み量・予算値が本文に記録される。要求した処理はその場では続行できないが、アプリの動作と既に開いている対象の表示は継続する。 | 開いている対象をいくつか閉じてから再試行してください。対象端末の実装メモリに余裕がある場合は、`hakutaku.yaml` の `memory.budget_mib` を引き上げる方法もあります。ソフトしきい値への到達（先読み停止・バッファ解放でアプリが自動的に縮退する状態）はこのコードになりません。 | `PERF-008`、`PERF-010` |
