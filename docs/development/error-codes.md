# エラーコード体系

- 状態: 採用済み（Accepted）
- 管理責任者: リポジトリメンテナー
- 最終更新日: 2026-08-11

本書の状態は、この変更が `main` へマージされた時点で採用済みになります。

## 目的

本書は、診断ログの `code=` 欄（`DIAG-005`）へ記録するアプリ内エラーコードの書式、領域の割り当て、採番手順の正本です。目的は次の2点だけです。

- 別モジュールが同じコードを採番し、ログから発生源を特定できなくなる事故を防ぐ
- 文言の変更やコードの移動があっても、手順書や問い合わせ対応が同じ失敗を同じ名前で参照できるようにする

エラーの内容そのものは、利用者向けには `ERR-002`（[機能要件](../requirements/functional.md)）の文章、診断ログには本文と `at=`（内部位置）が正本です。エラーコードはそれらを置き換えず、版をまたいで安定した参照名だけを提供します。決定の背景と代替案（エラーコードを設けない案を含む）は [ADR-0002](../architecture/decisions/0002-error-code-scheme.md) を参照してください。

## 適用範囲と割り当て基準

エラーコードは、すべてのエラーに必須ではありません。次のいずれかに当てはまる失敗にだけ割り当てます。

- 起動できない、または処理を継続できない失敗
- 利用者または導入組織側の対処（Runtime の導入、権限の付与、設定の修正など）が必要な失敗
- 手順書、FAQ、問い合わせ対応から参照される見込みのある失敗

該当しないエラーは、コードなし（診断ログでは `code=-`）で構いません。本文と `at=` で原因調査はできます（`DIAG-003`／`DIAG-004`）。

## 書式

`HKT-<領域>-<番号>`

- `HKT-`: 固定の接頭辞。OS やライブラリのエラーコード（例: ダイアログに表示する「OS エラーコード」）と区別する
- `<領域>`: 2〜4文字の英大文字と数字（先頭は英大文字）。下表で一意に割り当てる
- `<番号>`: 領域内の4桁ゼロ埋め連番。`0001` から始め、領域ごとに独立して数える

例: `HKT-W2-0007`

## 領域の割り当て

| 領域 | 対象 | 採番台帳 |
| --- | --- | --- |
| `W2` | WebView2 Runtime の検出、版判定、ACL、経路解決（起動ブートストラップ） | `src-tauri/src/bootstrap/runtime.rs` の `error_codes` モジュール |

新しい領域が必要になったら、この表へ行を追加する PR を作ります（コード追加と同じ変更でも構いません）。領域名は対象の責務を表す短い名前にし、既存行と重複させません。将来の候補（設定、データソース、パーサーなど）は、実装するクレート・モジュールが決まった時点で割り当て、先行予約はしません。

## 採番手順

1. 上の表で担当領域を確認する。なければ領域の行を追加する
2. その領域の採番台帳モジュールを開き、既存の最大番号に 1 を足した番号を割り当てる
3. 定数の doc コメントへ、失敗の意味と関連する要件 ID を書く

台帳の規則:

- 1つの領域の全コードは、1つの Rust モジュール（採番台帳）へ集約して定義する。台帳が複数箇所へ分かれた領域を作らない
- 一度 `main` へマージしたコードは、意味を変えず、番号を再利用しない。不要になった定数は削除してよいが、欠番として台帳へコメントを残す
- 同じ失敗には同じコードを使う。利用者側の対処が異なる失敗を、1つのコードへ束ねない
- コードを追加・変更・欠番化する PR は、同じ変更で利用者向け一覧表（[`docs/deployment/error-codes.md`](../deployment/error-codes.md)）を更新する

個別コードの一覧は各領域の台帳モジュールが正本であり、本書へ複製しません。

## 利用者向け表示との関係

利用者向けエラーは `ERR-002`（対象、位置、理由、継続可否、次操作）の文章が正本であり、エラーコードの併記は必須としません。現在の起動ブートストラップのダイアログはアプリ内エラーコードを表示していません。
