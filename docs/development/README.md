## 運用情報の正本

| 情報 | 正本 | 正本にしないもの |
| --- | --- | --- |
| 安定したリポジトリ規則 | このディレクトリ | チャットの記録、個人の記憶 |
| 個別タスクの目的、受け入れ条件、人間の責任者、動的状態 | GitHub Issue。小さな単発変更では PR。GitHub 権限のないローカル限定作業は、利用者が明示したタスクを暫定利用し、同一利用者が管理する一対一の引き継ぎだけを認める | ロードマップ、担当者のいないローカルメモ |
| 実装差分、検証、レビューの状態 | Issue に関連付けた下書きプルリクエスト（Draft PR）または PR | チャットの最終応答だけ |
| 実装中の共有可能な状態 | リモートへ送信済みのタスクブランチ | ローカルの worktree、stash、未コミット差分 |
| 長期優先順位 | [`docs/roadmap.md`](../roadmap.md) | 作業中タスクの一覧 |
| 製品・設計の判断 | 製品、要件、設計の各文書と採用済み（Accepted）の ADR | Issue のコメントだけ |
| AI への指示 | ルートの `AGENTS.md`。Codex、Claude Code など使用ツールを問わない | チャットの記録、ツール固有ディレクトリ内の未参照文書、ルートの `CLAUDE.md` などツール向け入口ファイル |

GitHub Projects を将来導入する場合は、集約する状態の正本を GitHub Projects に移すかを先に決めます。Issue、ラベル、GitHub Projects を同じ意味の手作業による状態管理として併用しません。

## 現在の段階

- 正式リリース前であり、`main` は開発版。詳細は[リポジトリ運用規則の「正式リリース前の方針」](repository-operations.md#正式リリース前の方針)を参照
- 実装技術（Rust + Tauri 2系）は [ADR-0001](../architecture/decisions/0001-rust-tauri-provisional-adoption.md) により暫定決定済み。確定は段階1（P13）の完了時
- ビルド、テスト、静的解析、整形の標準コマンドは[開発ワークフローの「段階0の標準検査」](workflow.md#段階0の標準検査)で確定済み。CI（`.github/workflows/ci.yml`）でも自動実行され、[`main` のブランチ保護](repository-operations.md#main-のブランチ保護)で必須化されている

利用可能な検査と手動確認を PR に記録し、未実施項目とリスクを明示します。

## 優先順位と矛盾

- セキュリティ事故と脆弱性報告では `.github/SECURITY.md` を優先する
- 製品仕様は採用済み（Accepted）の正本と ADR を優先する
- タスクの受け入れ条件が採用済み（`Accepted`）の正本と衝突する場合、実装で上書きせず、メンテナーが対象範囲または正本を更新する
- 運用文書同士が矛盾する場合、作業を安全側で停止し、この索引が示す正本へ集約する PR を作る

## 規則の変更

- 規則の変更は通常の Issue、PR、レビューを経る
- 同じ規則を複数文書へ複製せず、正本を変更して他はリンクまたは短い要約にする
- AI の毎回の行動を変える場合は、ルートの `AGENTS.md` の更新要否を確認する
- GitHub テンプレート、ブランチ保護、CI、リリース設定と文書を同じ変更で整合させる
- 繰り返した失敗やレビュー指摘は振り返り、再発防止が安定した規則なら文書へ反映する
