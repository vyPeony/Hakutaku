# 時間モデル

- 状態: 草案（Draft）
- 管理責任者: リポジトリメンテナー
- 最終更新日: 2026-08-18

## 目的

異なるデータソースの項目を時刻で検索、整列、相関するために、時刻の意味、精度、曖昧さ、順序の扱いを定義します。この文書は初期の判断項目を示すテンプレートであり、未決事項を補完や推測で隠しません。

## 時刻の種類

| 用語 | 意味 | 生成者 |
| --- | --- | --- |
| 出来事の時刻（Event time） | データソースが示す、出来事が発生した時刻 | データソースまたは生成元 |
| 観測時刻（Observed time） | Hakutaku またはコネクターが項目を観測した時刻 | Hakutaku |
| 取り込み時刻（Ingest time） | データソースのシステムがデータを取り込んだ時刻。現行のテキストログ閲覧では未使用（将来のデータソース追加時に使用）。 | データソースのシステム |
| 更新時刻（Modified time） | リソースまたは項目が更新されたとデータソースが示す時刻。現行のテキストログ閲覧では未使用（将来のデータソース追加時に使用）。 | データソースのシステム |
| 表示時刻（Display time） | UI でタイムゾーン変換・丸めを行った表示上の時刻 | ビューアー |

一つの項目が複数の出来事の時刻候補を持つ場合、コネクターは勝手に一つへ上書きせず、どのフィールドを代表値に選んだかと他の候補を来歴に残します。

## 時刻値が持つ情報

時刻は可能な範囲で次を組として扱います。

- 値
- 意味（出来事、観測、取り込み、更新など）
- 元のタイムゾーンまたは UTC オフセット
- 精度（日、秒、ミリ秒、データソースの刻みなど）
- 元表現
- 時計の基準または生成構成要素（分かる場合）
- 推論・補完・変換を行ったか

タイムゾーンまたはオフセットがない値を、暗黙に UTC や利用端末のタイムゾーンと断定しません。解釈が必要な場合は、接続またはリソース単位の明示設定と診断情報を使用します。現行リリースでは、タイムゾーン表記のない日時は常に端末のローカル時刻として解釈します（`LOG-012`）。将来のデータソース追加に伴い接続・リソース単位の明示設定が必要になった場合は、この解釈を見直します。

## 不明・曖昧な時刻

- 時刻がない項目も有効な項目として扱う
- 解析不能な元値をペイロードから失わず、診断情報を付ける
- 夏時間の重複・欠落時間を考慮する
- うるう秒、暦、ロケール固有表現の対応範囲を明示する
- 推論されたタイムゾーンと、データソースが明示したタイムゾーンを区別する
- 精度を超えた桁を、根拠なく補完しない

### うるう秒と時刻の範囲外表記

現行リリースのテキストログ日時解析（`LOG-DT-001`〜`LOG-DT-006`）は、時を `00`〜`23`、分と秒を `00`〜`59` の範囲でだけ受け付けます。したがって、**うるう秒表記（`23:59:60`）は日時として成立しません**。日の終わりを表す `24:00` や分が `60` の表記も同様です。うるう秒表を持たず、比較キーを 1 日 = 86,400,000 ミリ秒の固定換算で構築しているため、これらの表記へ意味を与える根拠を持たないのが理由です。成立しなかった行は破棄されず、「日時を持たない行」として扱います。直前に日時付きの行があればその継続行として結合し（`LOG-014`）、無ければ日時未確定の独立した項目にします。元の行の文字列はどちらの場合も失われません。既知の6書式より細かい小数秒（マイクロ秒など）を持つ行も、桁を黙って切り捨てず同じ扱いにします（`LOG-024`）。

## 時計のずれ

異なる端末またはサービスの時計が同期しているとは仮定しません。

- 相関では許容する時間幅と、その根拠を示す
- Hakutaku は時刻ずれ補正を行わず、ログに記録された日時をそのまま使用する（`LOG-016`）。
- 補正を行う場合、元時刻、補正量、補正根拠を保持する
- 観測時刻とネットワーク遅延から出来事の時刻を推測しない

## 順序

- 時刻印が同じ項目間の順序を保証しない
- データソース固有の連番、カーソル、オフセットがある場合は、時刻印と別に保持する
- 複数のデータソース間の全順序を暗黙に作らない
- 表示上の安定した並びには同順位の決定規則を使用し、そのフィールドを説明できるようにする
- ストリームの遅延到着、順序逆転、再送、重複を想定する

## 時刻範囲

範囲条件では、少なくとも次を明示します。

- 開始・終了を範囲に含むか含まないか
- どの時刻フィールドに適用するか
- 利用者入力とデータソースへのクエリでタイムゾーン変換が行われたか
- データソースの精度やクエリの意味により、範囲が拡張・丸められたか
- 現在時刻基準の相対範囲を、いつ評価したか

## 相関

時刻相関は「同じ時間帯にあるため関連候補である」ことを示し、因果関係や同一性を保証しません。

- 使用した時刻フィールド、時間幅、タイムゾーン、補正、追加識別子を表示できるようにする
- 時刻だけの一致と、trace ID 等を併用した一致を区別する
- 精度が粗い、タイムゾーン不明、時刻ずれ不明の場合は確信度を下げるか警告する
- 利用者が相関条件を確認・変更・解除できるようにする
- 自動相関は候補提示に留め、元の項目を変更・結合しない

## コネクターの責務候補

- 元の時刻印フィールドと表現を、ペイロードと来歴に保持する
- 出来事の時刻候補の選択規則を、コネクターのメタデータで説明する
- タイムゾーン、精度、時計の基準が不明な場合は、不明として返す
- データソースへのクエリに変換した時間範囲の意味を報告する
- 時刻印の解析失敗を項目全体の破棄理由にしない

## ビューアーの責務候補

- 元のタイムゾーンと表示用のタイムゾーンを区別する
- 変換・丸め・補正の有無を確認できるようにする
- 時刻のない項目を消失させず、別扱いで確認できるようにする
- 相関と並び順の根拠を表示できるようにする

## 受け入れシナリオ候補

1. UTC、明示されたオフセット、タイムゾーンなしの三種類を混在表示しても、元表現と解釈を追跡できる
2. 同一の時刻印を持つ項目が複数あっても、存在を失わず安定して表示できる
3. 時刻ずれのある二つのデータソースを相関するとき、時間幅と不確実性を確認できる
4. 時刻なし・解析不能の項目も、ペイロードと診断情報を確認できる
5. データソース側の時刻フィルターが丸められた場合、実際に適用された範囲を確認できる

## 未決事項

ストリーム更新・相対時間クエリは現行リリースの対象外（`LOG-010`、`LOG-028` 参照）。

- 代表となる出来事の時刻を選ぶ共通規則と、データソース固有の上書き
- 内部表現の精度、範囲、暦
- 相関の確信度の表現
