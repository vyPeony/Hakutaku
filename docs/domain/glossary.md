## 命名ルール

- 文書とコードでは、同じ概念に同じ名前を使う
- 一般語と区別する必要があるドメイン用語は、英語表記を併記する
- `Record`、`Event`、`Document` を表示単位の総称として混用せず、暫定的に項目（`Item`）を使う
- 新しい用語を導入する PR では、この文書へ定義と「何ではないか」を追加する

## 中核概念

| 用語 | 定義 | 例 | これは含まない |
| --- | --- | --- | --- |
| データソース（Data source / Source） | Hakutaku がデータを読み取る外部またはローカルの対象 | DB、ログサービス、API、ファイル | 接続設定そのもの |
| コネクター（Connector） | 一種類のデータソースと Hakutaku の読み取りモデルを橋渡しする境界 | PostgreSQL コネクター、JSON ファイルコネクター | UI 固有の表示ロジック |
| 接続プロファイル（Connection profile） | 接続先、対象範囲、非秘密設定、認証情報への参照をまとめた接続定義 | URL とデータベース名 | 認証情報の平文 |
| 認証情報（Credential） | データソースへのアクセスに使用する秘密 | トークン、パスワード、クライアント秘密情報 | 一般の接続設定 |
| リソース（Resource） | データソース内で列挙・選択できるデータの単位 | テーブル、ログストリーム、接続先、ファイル | 表示される個々の項目 |
| 項目（Item） | ビューアーで表示・検索される最小の論理単位 | 行、ログイベント、JSON オブジェクト | 常に永続 ID を持つとは限らない |
| ペイロード（Payload） | データソース由来の内容 | 行の列、ログ本文、API 応答の要素 | Hakutaku が付けた共通属性 |
| メタデータ（Metadata） | 項目の出所、時刻、識別などの共通属性 | データソース、リソース、観測時刻 | データソースの本文そのもの |
| スキーマ（Schema） | ペイロードの構造、型、制約について分かっている情報 | DB スキーマ、推論された JSON の構造 | すべての項目が固定形であるという保証 |
| 能力（Capability） | コネクターが提供可能と申告する機能 | ページ分割、ストリーミング、サーバー側の絞り込み | 全コネクターに共通の必須機能 |

## データアクセス概念

| 用語 | 定義 | 区別 |
| --- | --- | --- |
| クエリ（Query） | データソース側へ渡して実行される取得条件 | ビューアー内だけの絞り込みと区別する |
| 絞り込み（Filter） | 取得済み、または取得対象の項目を条件で絞る操作 | 全文検索や DB 固有のクエリと同一視しない |
| 検索（Search） | テキストまたは構造化条件で候補を探す利用者操作の総称 | 実行場所は能力により異なる |
| スナップショット（Snapshot） | ある時点または有限範囲の結果 | 継続更新するストリームと区別する |
| ストリーム（Stream） | 新しい項目を継続的に受け取る更新モデル | 定期的に再取得する定期取得と区別する |
| 定期取得（Polling） | 一定間隔でデータソースを再確認する更新モデル | 送信型のストリームと区別する |

## 閲覧と相関の概念

| 用語 | 定義 | 区別 |
| --- | --- | --- |
| 相関（Correlation） | 時刻、識別子、属性などを用いて関連項目を提示すること | データを合成する結合と区別する |
| 表示（View） | 項目の表示形式、列、並び、絞り込みなどの設定 | 接続先集合を含むワークスペースと区別する |
| ワークスペース（Workspace） | 調査対象の接続、リソース、表示、作業状態の集合 | 永続化・共有範囲は未決定 |
| 診断情報（Diagnostic） | 利用者が接続・取得・解析の問題を理解し、対処するための情報 | 閲覧対象のデータソースのログや、製品内部の開発ログと区別する |

時刻、順序、相関に関する詳細な意味は [時間モデル](time-model.md) を正本とします。

## セキュリティ概念

| 用語 | 定義 |
| --- | --- |
| 機密データ（Sensitive data） | 漏えい時に利用者、組織、システムへ影響するデータ |
| 秘匿化（Redaction） | 秘密または機密値を削除・置換して露出を防ぐこと |
| 秘密情報ストア（Secret store） | 認証情報を一般設定と分離して保管する、OS または外部の安全な機構 |
| 信頼境界（Trust boundary） | データと権限の信頼条件が変わる境界 |
