# ADR-0005: 設定の読み込みパスは絶対ローカルパス以外を検証エラーとする

- 状態: 採用済み（Accepted）
- 日付: 2026-08-01
- 管理責任者: リポジトリメンテナー

本 ADR の状態は、この変更が `main` へマージされた時点で採用済みになります。

## 背景

`CFG-010` は「読み込み対象にはローカルの絶対パスを使用する。相対パスとネットワーク共有パスは対応不要」と定めるが、**対応不要なパスが設定に書かれていた場合の挙動**を決めていない。入力資料 8.2 は「動作保証は行わない」とするのみである。

一方 `CFG-016` は「誤設定を黙って既定値に置換しない」ことを求めるため、**少なくとも黙って無視することはできない**。残る選択肢は「起動時検証でエラーにする（安全モードへ入る）」か「警告して当該項目だけ無効化し続行する」かであり、当時の計画正本（P03 設定）はこの判断を着手時の ADR に委ねていた。

## 判断の基準

- `CFG-016` の原則（誤設定を黙って通さない、理由を位置付きで示す）と整合すること
- 利用者（導入組織）が誤設定に確実に気づき、修正へ到達できること
- 「一部の設定だけが有効」という中間状態の複雑さを避けること
- 実装と検証の費用が小さいこと

## 検討した選択肢

1. 起動時検証エラーとし、安全モードへ入る（他の不正値と同じ扱い）
2. 警告を表示し、当該項目だけを無効化して続行する（部分適用）
3. 警告のみ表示し、そのまま使用を試みる（動作保証なしで通す）

## 決定

選択肢1を採用する。**相対パス、ネットワーク共有パス（UNC）、ドライブ相対パスなど、ローカルの絶対パス以外が読み込み対象に指定された場合、起動時検証のエラーとして扱い、`CFG-016` の安全モードへ入る。** エラーにはファイル名・行・列・理由（絶対ローカルパスが必要であること）を含める。

部分適用（選択肢2）を退ける理由:

- 「どの項目が生きているか」という中間状態が生まれ、利用者は一覧と警告を突き合わせないと現在の構成を判断できない。誤設定の見落としは、運用現場では「必要なログが出ていない」という形で顕在化し、原因調査の費用が大きい
- 検証の全体像（エラーは安全モード、正常は全適用）が単純に保たれ、`CFG-016` の実装・テストが一本化できる

選択肢3は `CFG-016` の趣旨（誤設定を黙って通さない）に反し、UNC パスの場合は意図しないネットワークアクセス（`SEC-001` の境界）にもつながるため退ける。

### パス種別の判定

- 許可: ドライブレター付きの絶対パス（例: `C:\Device\Logs`、`C:/Device/Logs`）
- エラー: 相対パス（`logs\a.log`）、ドライブ相対パス（`C:logs`）、ルート相対パス（`\logs`）、UNC パス（`\\server\share`、`\\?\UNC\...`）
- `\\?\C:\...` 形式（ローカルの verbatim パス）は絶対ローカルパスとして許可する

ログ解析プロファイルの `path_pattern`（glob）にも同じ規則を適用する（パターンの基点が絶対ローカルパスであること）。判定の実装は `crates/config` に置き、P05 の照合規則と共有する。

## 結果

### 良い影響

- 誤設定が起動直後に位置付きで顕在化し、修正までの動線が最短になる
- 設定の状態が「全適用」か「安全モード」の二値になり、実装・テスト・手順書が単純になる

### 悪い影響とトレードオフ

- 1 箇所のパス誤りで設定由来の機能全体が無効化される（安全モードの仕様どおり）。アドホックなファイル選択（`CFG-017`）は安全モードでも使えるため、業務が完全に止まることはない
- ネットワーク共有上のログを直接指定したい利用者には制約になる（`CFG-010` により初期リリースの対象外。ローカルへ複製して参照する運用を手順書で案内する）

## セキュリティとプライバシーへの影響

UNC パスを検証段階で拒否することで、設定起因の意図しないネットワークアクセスを起動前に遮断でき、`SEC-001`（参照内容を送信しない）の境界維持に寄与する。検証はパス文字列の形式判定のみで、ファイルシステムへのアクセスを伴わない。

## 移行または切り戻し

後続リリースでネットワーク共有パスへ対応する場合は、`CFG-010` の要件変更と新しい ADR で本判断を置き換える。判定は `crates/config` に閉じているため、緩和は局所的な変更で済む。

## 検証

- P03-1（設定スキーマ）の実装で、上記パス種別それぞれの検証結果（許可・エラー）が単体テストで確認できること
- 相対パス・UNC パスを含む設定で安全モードが起動し、位置と理由が表示されること

## 見直す条件

- ネットワーク共有パスの対応要望が要件化されたとき
- 部分適用を必要とする運用実態（多数のデータソース定義で1箇所の誤りが頻発する等）が確認されたとき
