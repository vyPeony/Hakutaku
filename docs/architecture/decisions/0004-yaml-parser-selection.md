# ADR-0004: YAML パーサーは saphyr の採用を確定する

- 状態: 採用済み（Accepted）
- 日付: 2026-08-01
- 管理責任者: リポジトリメンテナー

本 ADR の状態は、この変更が `main` へマージされた時点で採用済みになります。

## 背景

P01 は `hakutaku.yaml` の解釈を `crates/config` へ一本化し、YAML パーサーとして `saphyr` 0.0.11 を**暫定採用**した。パーサーの最終選定は P03 の判断事項として引き継がれており、本 ADR がその判断を記録する。

選定の必須条件は、`CFG-016`（安全モードでファイル名・**行・列**・理由を表示する）のために、**パーサーが値ごとの位置情報を保持すること**である。選定を誤ると、設定スキーマ実装後の差し替えになり費用が大きい。

## 判断の基準

- 値ごとの行・列の位置情報を取得できること（`CFG-016` の必須条件）
- 保守が継続しており、Rust 純正でネットワーク・ネイティブ依存がないこと（`SEC-001`、`VER-004`）
- API 変動のリスクを局所化できること
- 依存関係の追加が最小であること

## 検討した選択肢

1. `saphyr` の採用を確定する（P01 の暫定採用を継続）
2. `serde_yaml` へ差し替える
3. `yaml-rust2` へ差し替える
4. 自前の YAML サブセットパーサーを実装する

## 決定

選択肢1を採用し、`saphyr` を初期リリースの YAML パーサーとして確定する。

- `saphyr` は `MarkedYaml` により値ごとの行・列（`Marker`）を取得でき、`CFG-016` の必須条件を満たす。P01 の実装（`crates/config`）で取得できることを確認済み
- `serde_yaml` は 2024 年に保守終了（アーカイブ済み）であり、値ごとの位置情報の取得も直接はできないため退ける
- `yaml-rust2` は `saphyr` の前身であり、後継である `saphyr` 側で開発が継続している。前身へ戻す理由がない
- 自前実装は、YAML の仕様範囲の判断とテスト費用が過大で、初期リリースの目的に対して過剰なため退ける

`saphyr` は 0.0.x であり API 変動のリスクがあるため、次の封じ込めを維持する。

- `saphyr` への依存は `crates/config` の内部に限定し、公開 API（型・シグネチャ）に `saphyr` の型を露出しない（P01 で確立済みの構造を維持）
- バージョンは `Cargo.lock` で固定し、更新は通常の依存更新レビューで行う

## 結果

### 良い影響

- P01 の実装と検証をそのまま活かし、差し替え費用が発生しない
- 位置情報付きの検証エラー（`CFG-016`）を単一のパーサーで実現できる

### 悪い影響とトレードオフ

- 0.0.x のため、依存更新時に API 追随の作業が発生し得る（`crates/config` 内部に閉じるため影響は局所的）

## セキュリティとプライバシーへの影響

`saphyr` は純 Rust でネットワーク機能を持たず、`SEC-001`（参照内容を送信しない）に影響しない。設定ファイルの解釈は読み取り専用で、参照データに触れない。

## 移行または切り戻し

差し替える場合も `crates/config` の内部実装の変更に閉じる。公開 API を変えないことが封じ込めの条件であり、P03 の実装でもこれを維持する。

## 検証

- P03-1（設定スキーマ）の実装で、壊れた YAML と値不正に対しファイル名・行・列・理由を実際に表示できること
- `hakutaku-config` の公開 API が P01 の利用側（`bootstrap::runtime`）を壊していないこと（`cargo test --workspace`）

## 見直す条件

- `saphyr` の保守が停止した、または破壊的変更が継続してコストが看過できなくなったとき
- 位置情報・アンカー・マージキーなど、必要な YAML 機能の不足が実装で判明したとき
