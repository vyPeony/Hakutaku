# ADR-0008: 時系列マージの順序規則と source_ordinal を確定する

- 状態: 採用済み（Accepted）
- 日付: 2026-08-02
- 管理責任者: リポジトリメンテナー

本 ADR の状態は、この変更が `main` へマージされた時点で採用済みになります。

## 背景

P09（時系列統合表示）は、同一比較キーの行を「ファイルの表示順、次にファイル内の出現順」で決定的に並べる（4.2 の暫定方針）。しかし「ファイルの表示順」の定義がなく、定義しないと決定性（`LOG-007`）が成立しない。計画正本 `tasks/phase-09-timeline-merge.md` が推奨案を示し、ADR による確定を求めている。

## 判断の基準

- 同じ入力と設定に対し、繰り返し実行・再取得で順序が変わらないこと（調査の再現性）
- OS のファイル選択ダイアログの列挙順など、環境依存の順序に依存しないこと
- 項目の安定識別子（P04 の契約2）と独立であること

## 決定

計画正本の推奨案を採用する。

- 表示集合の世代ごとに不変な `source_ordinal` を各ソースへ割り当てる
  - 設定由来（`CFG-003`）: 設定に記載された順
  - 同一操作での複数選択: 正規化した絶対パスを第1キー ordinal case-insensitive、第2キー ordinal（大小区別）で並べてから追加（大小のみ異なるパスの決定性を第2キーで担保）
  - 後から追加: 既存の末尾へ追加
- 同一比較キーの同順位解決は `source_ordinal` → ソース内出現順（seq）
- **同一ファイルの重複選択はファイル識別子（ボリューム連番 + ファイルインデックス）で検出し、2件目以降を追加しない**（ハードリンク等の別名も1件として扱う。既に開いている旨を通知）
- 項目の安定識別子（`ItemId{source_id, seq}`）は `source_ordinal` に依存させない。将来の並べ替え操作は `source_ordinal` の更新 + 世代の前進として扱う
- 時刻補正は行わない（`LOG-016`。時計ずれはそのまま順序に現れ、読み込み元の識別が手がかり）

## 結果

- 良い影響: 同じログ群を選び直しても同じ順序が再現し、調査の再現性が保たれる
- 悪い影響: パス順というやや恣意的な順序が既定になる（明示的な並べ替え UI は後続の拡張余地）

## セキュリティとプライバシーへの影響

なし。

## 移行または切り戻し

マージ実装（P09）に閉じる。変更する場合は新しい ADR で置き換え、順序の互換性への影響を評価する。

## 検証

- P09 の受け入れ条件（繰り返し実行での順序再現、大小のみ異なるパスの決定性、重複選択の除外）の単体テスト

## 見直す条件

- タブの視覚的な並べ替え機能を提供するとき
