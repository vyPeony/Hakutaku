# ADR-0007: 再読み込みで合計 2 GB を超える場合は再読み込み全体を拒否する

- 状態: 採用済み（Accepted）
- 日付: 2026-08-01
- 管理責任者: リポジトリメンテナー

本 ADR の状態は、この変更が `main` へマージされた時点で採用済みになります。

## 背景

`PERF-006` は「開いているファイルの合計サイズ 2 GB」を最上位の拘束条件とし、`LOG-028` は「利用者が明示的に再読み込みを指示した場合に限り、対象を開き直して最新状態を反映する」ことを求める。外部プロセスが追記し続けるログでは、再読み込みの時点でファイルサイズが増えており、**反映すると合計が上限を超える**場合の挙動が仕様に記述されていない。計画正本 `tasks/phase-06-large-file-loading.md` は推奨案を示したうえで、着手時の ADR による確定を求めている。

## 判断の基準

- `PERF-006`（合計 2 GB が最上位）を、いかなる経路でも破らないこと
- 利用者が「いま何を見ているのか」を常に判別できること（部分的な最新化で表示の意味を曖昧にしない）
- `LOG-023`（削除・切り詰め・置換の検知による索引無効化）と矛盾しないこと
- 排他ロックを取らずに（`ERR-003`）実装できること

## 検討した選択肢

1. 再読み込み全体を拒否し、旧スナップショットの表示を維持する（計画正本の推奨案）
2. 上限に収まる範囲だけを部分的に読み込む
3. 上限超過分だけ他の対象を自動的に閉じて反映する

## 決定

選択肢1を採用する。挙動は次のとおり。

| 状況 | 挙動 |
| --- | --- |
| 再読み込み前の事前判定で合計が上限を超える | **再読み込み全体を拒否する。** 現在の合計、再読み込み後の見込み、上限値、閉じるべき対象を表示する |
| 純粋な追記であり、同一ファイルと確認できる | 従来のスナップショットを**旧 EOF（`snapshot_end`）に固定して表示を維持**し、「更新未反映」と示す |
| 削除・切り詰め・置換を検知 | `LOG-023` どおり索引を無効化する。従来の索引を有効扱いで維持しない |
| 他の対象を閉じたあと | 再試行できる |

「原子的」の適用範囲も計画正本のとおり確定する。

- **アプリ内の合計サイズの判定と予約**は、比較と確保（compare-and-reserve）を他の追加操作と競合しない形で行う（ここが原子的）
- ファイル側は観測した長さを `snapshot_end` として固定し、そこまでしか読まない。判定後の追記分は「更新未反映」とし、次の再読み込みで反映する（`LOG-010`、`LOG-028`）
- 縮小・置換はサイズ判定の対象にせず、`LOG-023` の無効化で扱う

選択肢2（部分読み込み）を退ける理由: 「最新状態の反映」（`LOG-028`）と「上限内」（`PERF-006`）の両方の意味を曖昧にし、利用者がどこまでが最新か判別できなくなる。選択肢3（自動クローズ）を退ける理由: 利用者が開いている対象をアプリの都合で閉じることになり、閲覧継続の原則（`ERR-001` の趣旨）に反する。閉じる対象の選択は利用者の判断に委ねる。

## 結果

### 良い影響

- `PERF-006` がすべての経路（初回追加・再読み込み）で一様に守られる
- 表示の意味（このスナップショットは `snapshot_end` まで）が常に明確

### 悪い影響とトレードオフ

- 上限付近で運用している利用者は、再読み込みの前に手動で対象を閉じる操作が必要になる（拒否メッセージで閉じるべき対象を示して補助する）

## セキュリティとプライバシーへの影響

なし。読み取り専用の原則（`ERR-003`）とロック非取得は変更しない。

## 移行または切り戻し

読み込み経路（P06）に閉じる。方針を変える場合は新しい ADR で置き換える。

## 検証

- P06 の受け入れ条件（上限付近での拒否表示、追記時の「更新未反映」、縮小・置換時の無効化、並行追加テスト）で確認する

## 見直す条件

- 対象端末の実機（P13）で上限付近の運用が頻発し、手動クローズの負担が問題になったとき
