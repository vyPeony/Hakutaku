# ADR-0011: クリップボードコピーは常に原文そのままとし、列の選択と quoted TSV を廃止する

- 状態: 採用済み（Accepted）
- 日付: 2026-08-21
- 管理責任者: リポジトリメンテナー

本 ADR の状態は、この変更が `main` へマージされた時点で採用済みになります。[ADR-0009](0009-clipboard-copy-format.md)を置き換えます（`Superseded`）。

## 背景

[ADR-0009](0009-clipboard-copy-format.md)は、コピー形式を「行（論理ログ項目）選択 = 原文そのまま、セル範囲選択 = 可逆な quoted TSV」と定めていました。セル範囲選択の入口は、ツールバーの「コピー列」チェックボックス（行番号／日時／本文）でした。

その後、[Issue #78](https://github.com/vyPeony/Hakutaku/issues/78) で行一覧の日時列を廃止しました。テキストログの原文は先頭に日時を含むため、その左に解析済みの日時列を置くと同じ日時が画面上で2回並んで見えていたためです。このとき、`LOG-024` が求める「解析した日時の元の精度（分、秒、1/100秒、1/1000秒）を、利用者への提示時に失わない」を満たす経路は、コピー列「日時」だけになりました。

つまりコピー列は、この時点で2つの役割を兼ねていました。

1. コピーする列を選ぶ（ADR-0009 のセル範囲選択）
2. 解析済み日時を画面外へ取り出す唯一の経路（Issue #78 以降）

[Issue #85](https://github.com/vyPeony/Hakutaku/issues/85) で、利用者はこの兼務をやめ、コピーを「常に原文そのまま」へ簡素化することを選びました。代わりに、実務で求められていた選択操作の拡張（飛び飛びの選択、ドラッグによる範囲選択）を行います。解析済み日時の提示は、時系列統合表示の改修（[Issue #82](https://github.com/vyPeony/Hakutaku/issues/82)）で正規化した日時の列として行う予定です。

## 判断の基準

- `COPY-002`（`Ctrl+C` でクリップボードへコピー）と `COPY-006`（明示的な操作時だけコピーする）を満たすこと
- `LOG-024` の「元の精度を保持する」義務を、保持と提示に分けて扱えること（保持は解析結果として維持し、提示手段は UI の設計判断とする）
- 貼り付け先での取り回しが、利用者の実運用（ログ本文をチャットや別のエディターへ貼る）に合っていること
- 選択の拡張（飛び飛び・ドラッグ）を、`PERF-012`（取得済みの行を累積しない）と両立できること

## 検討した選択肢

1. **コピーを常に原文そのままにし、列の選択と quoted TSV を廃止する**（採用）
2. コピー列を残したまま、選択操作だけを拡張する。日時の提示経路は現状維持
3. コピー列を廃止し、代わりに右クリックメニューへ「日時付きでコピー」を追加する

選択肢2は、Issue #78 以降のコピー列が持つ「日時を取り出す唯一の経路」という役割をそのまま残します。UI 上は「どの列をコピーするか」の設定に見えるため、日時を確認したい利用者がその機能へたどり着けるとは限らず、役割と見た目が一致しないままになります。

選択肢3は、形式を2通り（原文／日時付き）維持することになり、上限判定（`COPY-004`）とバイト数の算出も2通り必要になります。日時の提示という目的に対しては、[Issue #82](https://github.com/vyPeony/Hakutaku/issues/82) の統合表示改修で画面へ出すほうが直接的であり、コピー経路に形式の分岐を残す理由になりません。

## 決定

- **コピー内容は常に選択行の原文そのままとする。** 選択された範囲を `start` 昇順にたどり、項目の原文を改行（`\n`）で区切って連結する（末尾に改行は付けない。継続行を含む項目の内部改行はそのまま保つ）。この連結規則は ADR-0009 の「行選択」からそのまま引き継ぐ
- **列の選択（行番号・日時・本文の組）と quoted TSV を廃止する。** ツールバーの「コピー列」UI も廃止する
- **選択は互いに素な範囲の集合として表す。** クリック（単一）、`Shift+クリック`（アンカーからの範囲）、`Ctrl+クリック`（行単位の追加・除外による飛び飛びの選択）、ドラッグ（連続範囲。ビューポート端で自動スクロール）、`Ctrl+A`（全選択）で操作する（`COPY-001`）
- **上限判定（`COPY-004`／`COPY-005`）は、選択したすべての範囲の合計に対して行う。** 上限ちょうどは許可、超過のみ拒否、拒否時は部分コピーもクリップボードの変更も行わない（ADR-0009 から変えない）
- **範囲の集合は IPC 境界で検証する。** `start` 昇順・互いに素・行数1以上・表示集合の範囲内を満たさない要求は、コピーせずに拒否する（フロントエンドが正規化して送るが、コア層でも防御する）
- 初期リリースで Unicode プレーンテキスト（`CF_UNICODETEXT`）のみを載せることは変えない

## 結果

### 良い影響

- コピー結果が操作前から予測できる（「選んだ行がそのまま貼られる」以外の状態が無い）。列の組み合わせによって貼り付け結果が変わることがなくなる
- quoted TSV を解釈しない貼り付け先で内容が崩れて見える問題（ADR-0009 の「悪い影響」）が無くなる
- 生成規則が1通りになり、上限判定のバイト数算出も原文のバイト数と項目間の改行だけで済む
- コピー列 UI が無くなり、ツールバーが選択・ジャンプに専念する

### 悪い影響とトレードオフ

- **解析済み日時（元の精度を保持した表示文字列）を利用者へ提示する経路が、一時的に無くなる。** `LOG-024` の「保持」は解析結果として維持し続けるが、「提示」は [Issue #82](https://github.com/vyPeony/Hakutaku/issues/82) の統合表示改修まで画面に現れない。利用者はこの制約を了承済み
- 行番号を含めて貼り付けたい場合の手段が無くなる（原文の中の行番号情報は元ログの記載に依存する）
- 選択が「1つの連続範囲」から「範囲の集合」になり、状態遷移（分割・結合）の複雑さが増す

## セキュリティとプライバシーへの影響

コピーは個人情報等の機密データが他アプリへ渡る経路であり、明示的な操作時だけに限定します（`COPY-006`、`SEC-004`）。この点は ADR-0009 から変わりません。

原文そのままにしたことで、コピー内容に含まれ得る情報は「選択した行の原文」だけになり、解析済み日時という派生値が渡らなくなります（機密の観点では減る方向）。選択が無い場合・範囲の検証に失敗した場合は、クリップボードに一切触れません（空文字列で上書きもしません）。

## 移行または切り戻し

コピー生成（`crates/core-services/src/copy.rs`）、`copy_selection` コマンド（`src-tauri/src/clipboard.rs`）、選択モデル（`src/selection.js`）、ログ表示ビュー（`src/log_view.js`）、ツールバー（`src/index.html`）に閉じます。保存形式・設定ファイル・索引には影響しません（`CFG-018` の上限値の意味も変わりません）。

`copy_selection` の引数は `{ start, count, columns }` から `{ ranges: [{ start, count }, ...] }` へ変わります。フロントエンドとバックエンドは同じ配布物に含まれるため、版をまたぐ互換性の考慮は不要です。

切り戻しは Git 履歴から可能ですが、形式変更は貼り付け先の作業手順に影響するため、戻す場合も新しい ADR を要します。

## 検証

- `crates/core-services/src/copy.rs` の単体テスト: 複数範囲の昇順連結、隣接範囲が1範囲と同一になること、合計に対する上限判定（行数・バイト数の境界値）、検証の拒否（範囲なし・行数0・逆順・重なり・範囲外）、本文を読み出せない場合の中止
- `scripts/check-selection.mjs`（CI の `quality` ジョブ）: 選択モデルの純粋関数（範囲の分割・結合、ドラッグ更新、クランプ、二分探索、コピー範囲への変換）
- `scripts/gui/scenarios/06-select-and-copy.mjs`（手動実行の GUI 検査）: `Ctrl+A` → `Ctrl+C`、`Ctrl+クリック`の追加と除外、ドラッグによる連続範囲、飛び飛びの選択でのコピー完了通知の行数
- [手動での動作確認手順](../../verification/manual-check.md)の「選択とクリップボードコピー」

## 見直す条件
