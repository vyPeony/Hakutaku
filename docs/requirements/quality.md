# 品質要件

- 状態: 採用済み（Accepted）

- 要件の基準: Hakutaku 初期仕様 版 1.10

## 測定方針

本書は性能・メモリ・動作環境の確定要件を定義します。本書の状態は、この変更が `main` へマージされた時点で採用済みになります。

性能値は、対象 PC、ストレージ、エンタープライズ向けセキュリティソフト、入力データ、同じ端末で稼働する他の業務ソフトウェアの稼働状態と組にして記録します。初回表示時間には一律の秒数目標を設けず、他の業務ソフトウェアの稼働中の測定を合否の基準とします。段階0の性能値は参考値であり、段階1の LTSC 実機検証で最終判定します（`PERF-009`、`PERF-015`、`VER-005`、`VER-006`）。

## 性能・メモリの確定要件

| ID | 要件 |
| --- | --- |
| PERF-001 | 多数のファイルを扱えること。 |
| PERF-002 | 単一の巨大ファイルを扱えること。 |
| PERF-003 | 実装技術および設計の判断では高速性を重視すること。 |
| PERF-004 | 単一ファイルは最大約 1 GB を想定する。ただし、そのファイルを追加した後も `PERF-006` の合計 2 GB 上限を満たす場合に限り開ける。 |
| PERF-005 | 同時に最大約10ファイルを開く可能性を想定する。ただし、10ファイルの合計が `PERF-006` の 2 GB 以内である場合に限る。 |
| PERF-006 | 同時に開くファイルの合計サイズ 2 GB を、ファイル単位サイズおよびファイル数より上位の拘束条件とする。上限を超えるファイルの追加を拒否する。 |
| PERF-007 | 10万行を超える既存ログがあるため、少なくとも10万行超を現実的な性能試験条件に含める。行数だけの上限は設けず、`PERF-004`～`006` のファイルサイズ・ファイル数・合計サイズを拘束条件とする。 |
| PERF-008 | メモリ上限は、**Rust コアプロセスのヒープ確保量の合計**（ログ本文バッファ、索引、デコード結果、DB 取得ページ、DICOM 解析結果、コピー用バッファなど、Hakutaku 自身と利用クレートによる未解放確保量）に対する予算とする。別プロセスである WebView2 プロセス群の使用量は含まない（`PERF-011`、`PERF-012`）。初期値は 2 GB とし、設定ファイルで変更できること。 |
| PERF-009 | 初回表示時間に一律の秒数目標は設けない。動作環境やエンタープライズ向けセキュリティソフトの影響を考慮して評価する。 |
| PERF-010 | メモリ会計をコア設計の一部として初期実装から組み込み、後付けにしない。予算判定は `PERF-008` のヒープ確保量に対して行い、大規模読み込み前の予約・拒否を必須とする。 |
| PERF-011 | Hakutaku の Rust コアプロセスと、Tauri／WebView2 が起動した Hakutaku 専用の子プロセス群について、Windows `PROCESS_MEMORY_COUNTERS_EX.PrivateUsage` の合計を参考指標として計測し、`PERF-008` の予算値 + 1 GB を超えないことを性能試験で確認する。この値は予算の合否判定基準とはせず、ワーキングセットも判定に使用しない。「+ 1 GB」は WebView2 の複数プロセス構成を前提とした暫定値であり、技術試作の実測により再確定する。 |
| PERF-012 | フロントエンド（WebView2 側）は、可視範囲と前後の一定バッファに限って行データを保持し、取得済みの行を累積しないこと。保持する行数およびバイト数の上限を設け、上限を超えた場合は表示範囲から遠い範囲を破棄し、必要時に Rust コアから再取得すること。上限値は設定できること。 |
| PERF-013 | `PERF-008` の予算は Rust コアプロセスのみを対象とするため、フロントエンド側の累積はこの予算では検知できない。`PERF-012` の上限を、フロントエンド側メモリに対する一次的な歯止めとして扱う。 |
| PERF-014 | 運用先の専用端末で実行する場合に他の業務ソフトウェアの動作を阻害しないよう、資源使用を抑制する手段を提供すること。少なくとも、解析の同時実行数の上限、読み込み時の I/O 発行間隔、および Hakutaku プロセスの優先度を通常以下に設定できること。既定値は運用先の専用端末での実行を前提に控えめに定める。`Q-039` により、資源状況を監視して自動的に抑制する機構は必須要件としない。 |
| PERF-015 | 性能試験は、**同じ端末で稼働する他の業務ソフトウェアが稼働している状態**と、稼働していない状態の双方で実施し、両方の実測値を記録すること。合否は他の業務ソフトウェアの稼働中の値を基準とする。 |
| PERF-016 | Hakutaku はいつでも安全に停止できること。実行中に利用者が終了させた場合、またはタスクマネージャー等で強制終了された場合も、参照対象のログ・DICOM・データベースに影響を与えず、同じ端末で稼働する他の業務ソフトウェアの動作を妨げないこと。次回起動時に `temp` の残存ファイルを清掃する（`SEC-006`）。 |

## 動作環境の確定要件

| ID | 項目 | 要件 |
| --- | --- | --- |
| ENV-001 | OS | 主たる対象は **Windows 10 IoT Enterprise LTSC**（最も古い機種で version 1809 / build 17763 相当と想定）の64ビット版とする。機種によりバージョンが異なるため、単一バージョンを前提としない。Windows 11 および通常版 Windows 10 も対象に含める。Windows 7 および32ビット版は対象外。 |
| ENV-002 | CPU | 機種により不定。特定の CPU モデルを前提としない。 |
| ENV-003 | メモリ | 搭載メモリは最低 8 GB。`ENV-010` により運用先の専用端末上で他の業務ソフトウェアと同時に稼働するため、Hakutaku が全量を利用できる前提にしない。メモリ予算の初期値は 2 GB とする（`PERF-008`）。対象端末上で他の業務ソフトウェアの動作に影響が出る場合は、設定でさらに引き下げて運用できること。 |
| ENV-004 | ストレージ | SSD を主に想定するが、HDD の可能性も考慮する。 |
| ENV-005 | 画面解像度 | 1920×1080 を基準とする。 |
| ENV-006 | ネットワーク | 基本的にオフラインで利用できること。 |
| ENV-007 | UI 言語 | 日本語のみ。 |
| ENV-008 | 想定環境 | 対象端末の Microsoft Edge および WebView2 Evergreen Runtime の導入状況は**機種により異なる**。多くの機種では導入済みだが、一部の古い機種では未導入である。したがって `DIST-006` の Evergreen 経路と Fixed Version 経路は**どちらも実運用で発生する**。いずれか一方を例外扱いせず、両経路を保守・検証の対象とする。 |
| ENV-009 | 導入時の制約 | 実行ファイル直下への `WebView2` フォルダの作成、および Fixed Version Runtime の持ち込み・配置に、運用上の制約はない（`Q-036`）。管理者権限を要する操作を前提としない範囲で、`DIST-006`～`017` を適用できる。 |
| ENV-010 | 実行形態 | **主たる実行場所は運用先の専用端末とする**（`Q-037`）。同じ端末で稼働する他の業務ソフトウェアが稼働している状態で、同一 PC 上で Hakutaku を起動して調査する運用を標準ケースとして設計する。開発用 PC など運用先の専用端末以外の Windows 環境でも同じ実行ファイルで動作すること。実行場所によって機能差を設けない。 |
| ENV-011 | 資源の共有 | 運用先の専用端末で実行する場合、CPU、メモリ、ディスク I/O を他の業務ソフトウェアと共有する。**他の業務ソフトウェアの動作を阻害しないことを、Hakutaku 自身の処理速度より優先する**（`PERF-014`）。 |
| ENV-012 | 異常時の運用 | 対象端末上で異常が発生した場合、**Hakutaku を停止して構わない**（`Q-039`）。Hakutaku 側で自動的に資源を検知・抑制する機構は必須としない。ただし、停止・強制終了によって参照対象および他の業務ソフトウェアへ影響が出ないこと（`PERF-016`）。 |

## 暫定的な受け入れ条件

次は確定要件を検証する現時点のシナリオです。対応する ID 付き要件の本文を変更せず、試作結果に応じて測定手順を改訂できます。

- 1 GB 以下の単一ログ、10ファイル以下かつ合計 2 GB 以下の複数ログ、10万行超および約2000万行規模の代表データを使う。
- 合計 2 GB を超える追加は、既存表示を維持したまま拒否し、理由と上限を表示する。
- Rust コアのヒープ予算は初期値 2 GB とし、変更時は設定値を予算にする。大規模確保前の予約・拒否を確認する。
- Rust コアと Hakutaku 専用 WebView2 子プロセス群の `PrivateUsage` 合計を測定し、参考指標として「予算値 + 1 GB」と比較する。これはヒープ予算の合否判定に代用しない。
- 連続スクロール後も WebView2 プロセス群のメモリが単調増加し続けず、表示範囲から遠い行を破棄・再取得できることを確認する。
- SSD と HDD の双方、同じ端末で稼働する他の業務ソフトウェアが稼働中・停止中の双方で測定し、他の業務ソフトウェアの稼働中の結果を合否に使用する。
- 読み込み中も UI 操作、進捗確認、キャンセルが可能であること、安全な終了・強制終了後も参照対象と他の業務ソフトウェアへ影響しないことを確認する。

## 暫定値と再確定条件

次は要件自体を未決にするものではなく、指定した検証で値を再確定する項目です。

- `PERF-011` の「予算値 + 1 GB」は WebView2 の複数プロセス構成を前提とした暫定値であり、技術試作で再確定する。
- `CFG-022` のフロントエンド保持行数・バイト数の初期値は、段階0の実測で決める。
- `PERF-014` の資源抑制の既定値と `ENV-001` の実機下限は、段階1で決める。
- 初回表示時間は固定秒数を採用せず、測定条件ごとの回帰として管理する。
