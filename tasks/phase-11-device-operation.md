# P11 対象端末での運用適合（昇格・資源抑制・安全な停止）

- 状態: 草案（Draft）
- 開始条件: P06 の完了ゲート（抑制の接続点）と P01 の完了ゲート（診断ログ）を満たすこと
- 前提フェーズ: P06
- 段階: 段階0（既定値の確定は P13）
- 期待成果物: アクセス拒否時の昇格経路、資源抑制の設定と既定値、安全な停止と `temp` の清掃
- 予定変更範囲: コア側のプロセス起動・優先度制御、抑制の適用、GUI 側の昇格操作、終了処理

## 目的

`ENV-010` により、Hakutaku の**主たる実行場所は対象端末**です。他の業務ソフトウェアが稼働している同一 PC 上で調査する運用が標準ケースです。このフェーズは、その環境で他の業務ソフトウェアを妨げずに動くための要件をまとめて扱います。

`ENV-011` が優先順位を明示しています。

> 対象端末で実行する場合、CPU、メモリ、ディスク I/O を他の業務ソフトウェアと共有する。**他の業務ソフトウェアの動作を阻害しないことを、Hakutaku 自身の処理速度より優先する。**

三つの主題（権限昇格、資源抑制、安全な停止）を同じフェーズに置く理由は、いずれも「対象端末で他の業務ソフトウェアと共存する」という同一の運用条件に由来し、個別に扱うと優先順位の判断が分散するためです。

## 対象要件

### 権限昇格

| ID | 要求の要旨 |
| --- | --- |
| `PROD-012` | 通常プロセスは非昇格で起動する。アクセス拒否時にユーザーが選択した場合だけ、Windows の昇格機構で新しい Hakutaku プロセスを起動する。実行中プロセス自体が昇格するものとは扱わない |
| `PRIV-001` | 通常は Windows の `asInvoker` 相当の非昇格プロセスとして起動する。常時管理者権限を要求しない |
| `PRIV-002` | 参照対象へのアクセスが拒否された場合、理由を表示し、ユーザー操作により `runas` 相当で新しい昇格済みプロセスを開始できる |
| `PRIV-003` | 元の非昇格プロセスは開いた状態を維持し、昇格プロセスへ既存タブ、表示位置、解析済みデータを自動転送しない。昇格プロセスでは対象を選び直す |
| `PRIV-004` | 昇格が拒否・キャンセル・ポリシーで禁止された場合、元プロセスを終了せず、アクセスできなかった対象だけをエラーにする |
| `DIAG-007` | 昇格プロセスが出力した診断ログを非昇格プロセスから書き込めない場合も `DIAG-006` に従う。昇格プロセスの出力であることが判別できる |

UAC の有効・無効や資格情報入力の要否は Windows のポリシーに従います。「UAC が存在しない環境」という独自状態は定義しません（10.5）。

### 資源抑制

| ID | 要求の要旨 |
| --- | --- |
| `PERF-014` | 資源使用を抑制する手段を提供する。少なくとも、解析の同時実行数の上限、読み込み時の I/O 発行間隔、Hakutaku プロセスの優先度を通常以下に設定できる。既定値は対象端末での実行を前提に控えめに定める |
| `CFG-024` | 解析の同時実行数、I/O 発行間隔、プロセス優先度を設定できる |
| `ENV-010` | 主たる実行場所は対象端末。開発用 PC でも同じ実行ファイルで動作し、実行場所による機能差を設けない |
| `ENV-011` | 他の業務ソフトウェアの動作を Hakutaku 自身の処理速度より優先する |
| `ENV-012` | 異常時は Hakutaku を停止してよい。資源状況を監視して自動的に抑制する機構は必須要件としない |
| `ENV-003` | 対象端末で他の業務ソフトウェアと同時稼働するため、搭載メモリの全量を利用できる前提にしない。設定でさらに引き下げて運用できる |

**資源状況を監視して自動的に抑制する機構は実装しません**（`ENV-012`、`Q-039`）。`PERF-014` の設定値による静的な抑制と、`PERF-016` の安全な停止で対応します。

### 安全な停止

| ID | 要求の要旨 |
| --- | --- |
| `PERF-016` | いつでも安全に停止できる。利用者による終了、タスクマネージャー等による強制終了でも、参照対象のログ・DICOM・DB に影響を与えず、他の業務ソフトウェアの動作を妨げない。次回起動時に `temp` の残存ファイルを清掃する |
| `SEC-006` | 一時ファイルは `temp` 配下に限定し、正常終了時に削除し、次回起動時にも残存を清掃する |
| `ERR-003` | 参照元ファイルを変更せず、不要なロックやタイムスタンプ変更を避ける |

## 作業項目

1. **非昇格起動の確認。** `asInvoker` 相当で起動することをマニフェストで固定します。常時管理者権限を要求しません。
2. **アクセス拒否の検出と表示。** 参照対象へのアクセスが拒否された場合、理由を表示します。`ERR-002` の共通エラー形式を使います。
3. **昇格プロセスの起動。** ユーザーが選択した場合だけ、`runas` 相当で**新しい Hakutaku プロセス**を開始します。
   - **実行中プロセス自体が昇格するものとは扱いません**（`PROD-012`）
   - 元の非昇格プロセスは開いた状態を維持します（`PRIV-003`）
   - 既存タブ、表示位置、解析済みデータを自動転送しません。昇格プロセスでは対象を選び直します
4. **昇格失敗時の扱い。** 拒否・キャンセル・ポリシー禁止の場合、元プロセスを終了せず、アクセスできなかった対象だけをエラーにします（`PRIV-004`）。
5. **診断ログの昇格判別。** 昇格プロセスの出力であることを判別できる形にします（形式は P01 で用意）。非昇格プロセスが書き込めない場合も `DIAG-006` に従い、通知して診断ログなしで動作を継続します。
6. **抑制設定の適用。** P06 が用意した接続点へ、`CFG-024` の値を適用します。
   - 解析の同時実行数の上限
   - 読み込み時の I/O 発行間隔
   - Hakutaku プロセスの優先度（**通常以下**に設定できること）
7. **既定値の暫定決定。** 対象端末での実行を前提に控えめな既定値を置きます。**確定は P13 の実測です**（`VER-006`）。
8. **安全な停止。** 正常終了時に `temp` を削除します。強制終了された場合に備え、次回起動時にも残存ファイルを清掃します（P01 で実装済みの経路を利用）。
   - 強制終了で参照対象が変化しないことを確認します。書き込みを行わない設計（`ERR-003`）がその根拠です
9. **実行場所による機能差の排除。** 対象端末と開発用 PC で同じ実行ファイルが同じ機能を提供することを確認します（`ENV-010`）。

## 影響

- **セキュリティ:** 昇格プロセスの起動は権限の境界を越える操作です。**ユーザーが明示的に選択した場合だけ**行います。自動昇格や、昇格を促す既定動作を作りません
- **データ:** `PERF-016` により、強制終了でも参照対象を壊しません。読み取り専用の設計（`ERR-003`）と、書き込み先を `logs`／`temp`／`WebView2` に限定していること（`SEC-009`）がその根拠です
- **性能:** **抑制設定は Hakutaku 自身の性能を意図的に下げます。** `ENV-011` により、これは正しい方向です。抑制を強めた状態での読み込み時間を記録します
- **互換性:** 既定値を後から変えると、既存の導入先で挙動が変わります。P13 で確定させ、それ以降は変更に理由を要します

## リスクと未決事項

### 確定要件に起因するもの

- **`PRIV-003` により、昇格プロセスでは対象を選び直す必要があります。** 利用者から見ると「同じ作業をやり直す」ことになり、不便に感じられ得ます。仕様上の判断であり、状態の自動転送は実装しません
- `PERF-014` の既定値を「控えめ」に定めると、開発用 PC での体感性能が低下します。`ENV-010` により実行場所で機能差を設けられないため、**設定で調整する以外の手段がありません**。この前提を利用者向け説明に反映する必要があります

### 暫定設計に起因するもの

- I/O 発行間隔の実装方法（読み込みごとの待機、帯域制限など）は設計判断です
- プロセス優先度をいつ設定するか（起動時か、読み込み開始時か）も設計判断です

### 人間判断待ち

- **`CFG-024` の具体的な既定値が未決です。** 「対象端末での実行を前提に控えめに定める」という方針だけがあり、具体値は対象端末での実測（P13）を待ちます。段階0では暫定値を置きます
- 昇格プロセスを起動する操作の見せ方について、利用者の確認が望ましいです。誤って常用されると `PRIV-001` の趣旨（常時管理者権限を要求しない）が損なわれます

## 完了ゲート

- 非昇格で起動し、アクセス拒否時に昇格プロセスを起動でき、失敗しても元プロセスが生き残る
- 同時実行数、I/O 間隔、プロセス優先度が設定でき、実際に効く
- 正常終了と強制終了の両方で参照対象が変化せず、`temp` が清掃される
- 段階1で確認すべき事項が「他の業務ソフトウェアとの同時稼働」だけに絞られている
