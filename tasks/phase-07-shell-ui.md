# P07 共通シェル UI とアドホックなファイル選択

- 状態: 草案（Draft）
- 開始条件: P04 の完了ゲートと、**P04-6（進捗・エラー・キャンセルの共通契約）**が満たされていること。**P06 の完成は開始条件ではありません**
- 前提フェーズ: P04（P05・P06 と並行して着手可能。ただし完了は P06 との結合後）
- 段階: 段階0
- 期待成果物: 参照対象一覧、ビューのタブ、状態・エラー表示領域、進捗とキャンセルの操作、ファイル選択 UI、安全モードの表示
- 予定変更範囲: GUI 側の共通シェル、ファイル選択のコマンド、エラー表現の共通化

## 目的

形式別ビューアを載せる「共通シェル」を作ります。あわせて、設定ファイルに記載のない任意のファイルをアドホックに開く経路を完成させます。

入力資料 3.2 の暫定方針が、このフェーズの範囲です。

> 起動後の共通画面に、参照対象一覧、開いているビューのタブ、状態・エラー表示領域を設ける。

`PROD-016` は形式共通の要件であり、DICOM ビューアを追加する後続リリースでも同じ経路を使います（`DCM-008`、`DCM-009`）。そのため**形式に依存しない設計にします**。

### 開始依存と完了依存を分ける

このフェーズは P05・P06 と並行して着手できますが、**完了は P06 との結合を待ちます**。両者を混同しないでください。

| 区分 | 条件 |
| --- | --- |
| **開始依存** | P04 の完了ゲートと P04-6（進捗・エラー・キャンセルの共通契約）。契約に対して試験用の疑似データ（fixture）で実装を始められます |
| **完了依存** | P06 との結合。「進捗とキャンセルが実際に機能する」ことは、P06 の読み込み実装がないと確認できません |

したがって、レイアウト、状態管理、エラー表現、ファイル選択は P06 と並行して進められます。進捗・キャンセルの動作確認だけが P06 の完成待ちです。

## 対象要件

| ID | 要求の要旨 |
| --- | --- |
| `PROD-005` | 画面またはビューを切り替えて複数形式を扱える、拡張可能なマルチフォーマットビューアとする |
| `PROD-016` | 設定ファイルに記載のない任意のローカルファイル・フォルダを、実行中のファイル選択 UI からアドホックに開ける。設定編集とアプリ再起動を必須としない |
| `LOG-020` | 設定ファイルに記載されていない任意のローカルログファイルも、ファイル選択 UI からアドホックに開ける |
| `CFG-017` | 設定ファイルは起動時のショートカット、既定値、解析プロファイルを提供するものであり、アドホックな選択の前提条件ではない |
| `CFG-015` | 設定がない初回起動でも、組み込み既定値で起動しアドホックなファイル選択を利用できる。設定未検出を非致命的な通知として表示する |
| `CFG-016` | 設定が不正な場合、安全モードで UI を起動し、ファイル名・行・列・理由を表示する |

| `CFG-003`／`PROD-006` | 設定で事前定義したパスを参照対象として表示する |
| `CFG-010` | 読み込み対象はローカルの絶対パス |
| `PROD-015`／`ENV-007` | UI の表示言語は日本語のみ |
| `ENV-005` | 1920×1080 を基準とする |
| `EXT-001` | 新しい非テキスト形式を将来追加でき、画面を切り替えて閲覧できる設計とする |
| `LOG-015` | 統合表示 OFF 時はファイル別タブで表示を切り替える。分割表示は不要 |
| `LOG-022` | 曖昧な場合にプロファイル選択を求める経路（UI 側） |

## 作業項目

1. **共通シェルの構成。** 参照対象一覧、開いているビューのタブ、状態・エラー表示領域を配置します。`ENV-005` の 1920×1080 で、スクロールやダイアログの画面外配置なしに操作できることを確認します。
2. **参照対象一覧。** 設定で事前定義したパス（`CFG-003`）と、アドホックに開いた対象を同じ一覧に表示します。各対象の状態（読み込み中、読み込み済み、エラー、変更済み）が分かるようにします。
3. **ファイル選択 UI。** 任意のローカルファイル・フォルダを選べるようにします。**設定編集とアプリ再起動を必須としません。** フォルダ選択は DICOM ビューア（P14）で使いますが、経路は形式共通にします。
   - `SEC-012` により、フロントエンドへ任意パスのファイルアクセス権を与えません。選択結果は Rust コマンドへ渡し、読み取りは Rust 側で行います
4. **エラー表現の共通化。** `ERR-002` の要素（対象の名称またはパス、発生位置、理由、継続可否、必要な次操作）を持つ共通の型を定義し、全フェーズが同じ形でエラーを返せるようにします。
   - `ERR-002` は「`DIAG-003`／`DIAG-004` により実値の表示を制限しないため、原因調査に必要であればフルパスを表示してよい」と定めています。**マスキングしません**
5. **部分的な失敗への耐性。** 一つの対象の失敗で他の対象の閲覧を止めません。失敗した対象を一覧上で識別でき、再試行できるようにします（`LOG-027` の再試行と連動）。
6. **進捗とキャンセル。** P06 の通知経路を受けて、進捗、処理中の対象、失敗した対象を表示します。キャンセル操作を提供します。
7. **設定未検出と安全モードの表示。** `CFG-015` の非致命的な通知と、`CFG-016` の安全モード（ファイル名・行・列・理由）を表示します。**安全モードでもアドホックなファイル選択が使えることを確認します。**
8. **プロファイル選択の要求。** `LOG-022` で自動判定が曖昧だった場合に、プロファイルの選択を求める UI を提供します。選択しない場合は日時未解析の生表示にします。
   - **追加機能:** 同じ UI で日時書式（`LOG-DT-001`〜`006`）も直接選べます。`log_profiles` に定義がないアドホックなファイル（設定を書かずに開いた `LOG-DT-004` のみのログなど）は、プロファイルの選択肢では解決できないためです。手動で選んだ書式は、プロファイルの `datetime_format` 設定より優先されます
9. **タブ切り替え。** 統合表示 OFF 時のファイル別タブを提供します（表示内容の実装は P08）。分割表示は作りません（`LOG-015`）。
10. **形式追加の余地。** 形式別ビューアを載せる境界を定義します。`9.2` の責務分離（データソース、形式判定、パーサー、ビュー、共通サービス）に対応させます。

## 影響

- **セキュリティ:** ファイル選択の結果をフロントエンドがパスとして保持し続けると `SEC-012` の趣旨に反します。ソース識別子で参照する設計にします
- **データ:** `ERR-002` によりフルパスと実値を表示します。画面に個人情報等の機密データが出る前提であり、マスキングしません（`SEC-007` により機密データのマスキング表示を提供しません）
- **性能:** 一覧とタブの描画は対象数が10程度（`PERF-005`）なので影響は小さい見込みです。DICOM の 1 万ファイル（`DCM-019`）では仮想化が必要になりますが、それは P14 です
- **互換性:** 共通シェルの境界は P14 の SQLite・DICOM ビューアが依存します。形式固有の前提を入れないことが重要です

## リスクと未決事項

### 確定要件に起因するもの

- `LOG-022` の「プロファイル選択を求める」か「日時未解析の生表示にする」の既定挙動が仕様上二択のままです。UI として両方を提供し、既定をどちらにするかは着手時に決めます
- `ERR-002` によりフルパスを表示するため、画面共有やスクリーンショットで個人情報等の機密データが流出し得ます。仕様上の判断（`DIAG-003`〜`005`、`SEC-005`）であり実装で制限しませんが、利用者向け説明が必要です

### 暫定設計に起因するもの

- 3.2 の「参照対象一覧、タブ、状態・エラー表示領域」という構成は暫定方針です。1920×1080 での実際の使い勝手により配置が変わり得ます
- 対象の状態（読み込み中／済み／エラー／変更済み）の分類は設計判断です

### 人間判断待ち

- 共通シェルの画面設計そのものについて、利用者の確認が必要です。入力資料は配置の方針までしか定めておらず、具体的な画面案はありません

## 完了ゲート

- 設定なし、正常な設定、壊れた設定の3状態すべてで、アドホックにログを開いて閲覧できる
- 一つの対象の失敗が他へ波及しない
- **P06 と結合した状態で**進捗とキャンセルが機能する
- 形式別ビューアを追加できる境界が定義されている

3番目は完了依存です。P06 が未完成の段階では、共通契約に対する疑似データでの動作までを確認します。
