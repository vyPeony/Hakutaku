# P01 起動ブートストラップと WebView2 経路

- 状態: 草案（Draft）
- 開始条件: P00 の完了ゲートを満たすこと。**Fixed Version WebView2 Runtime を入手済みであること**（下記「リスクと未決事項」）
- 前提フェーズ: P00
- 段階: 段階0（実機での再確認は P13）
- 期待成果物: Tauri 初期化前に動く Rust ブートストラップ、Runtime 解決の3経路、ネイティブダイアログによる失敗通知、`logs`／`temp`／`WebView2` の管理、診断ログ
- 予定変更範囲: `src-tauri/src/`（ブートストラップ）、コア側の診断ログクレート、Tauri の Capability と CSP 設定

## 目的

Tauri を初期化する**前**に動く Rust 側のブートストラップ処理を作ります。WebView2 Runtime の解決、ユーザーデータフォルダの確定、実行時フォルダの用意、診断ログの開始までをここで完結させます。

このフェーズを早い位置に置く理由は二つあります。

1. `VER-003` が「段階0であっても Evergreen Runtime の存在に依存した実装をしない」ことを求めています。Fixed Version 経路を後から足す形にすると、段階1で技術選定ごと崩れます
2. Runtime が見つからない場合の通知は Tauri を使えないため（`TECH-005`）、Tauri に依存しない通知経路を最初から用意する必要があります

### 実行時フォルダと診断ログ

| ID | 要求の要旨 |
| --- | --- |
| `DIAG-001` | 診断ログは実行ファイル直下の `logs` フォルダへ保存する。ほかの場所へは保存しない |
| `DIAG-002` | 既定のローテーションは1ファイル 10 MiB、5世代。設定で変更できる |
| `DIAG-003` | 診断に必要ならログ本文、DB セル値、DICOM タグ値、認証情報などの実値を出力してよい。マスキングを必須としない |

| `DIAG-006` | `logs` がなければ作成する。失敗した場合は理由を通知し、別の保存先へ自動フォールバックせず、診断ログなしで動作を継続する |
| `DIAG-007` | 昇格プロセスの出力を非昇格プロセスが書き込めない場合も `DIAG-006` に従う。昇格プロセスの出力であることが判別できる |

| `SEC-006` | 一時ファイルは実行ファイル直下の `temp` 配下に限定し、正常終了時に削除し、次回起動時にも残存を清掃する |
| `SEC-009` | 実行時に作成・書き込みするフォルダを `logs`、`temp`、`WebView2` に限定する。`%LOCALAPPDATA%` 配下へは書き込まない |
| `SEC-010` | `WebView2` フォルダの内容は個人情報等の機密データを含み得るものとして扱う。暗号化やアクセス制御は行わない |
| `CFG-020` | 診断ログのローテーションサイズと保持数を設定できる（設定の読み込みは P03） |

#### `SEC-001` はこのフェーズで完了しません

CSP（`SEC-011`）が制限するのは **WebView2 側**です。**Rust コアや追加した依存クレートによる外部通信は防げません。** したがって `SEC-001` は次のように扱います。

| 段階 | 扱い |
| --- | --- |
| このフェーズ | WebView2 側の経路を CSP で閉じる。Capability を最小化する（`SEC-012`） |
| **全フェーズ** | 「参照内容を外へ送らない」ことを**不変条件**として維持する。依存を追加するたびに外部通信の有無を確認する |
| P12 | 識別可能な合成本文を使い、**プロセス単位の送信監視**と依存・API の確認を行うゲートを通す |

依存クレートが将来テレメトリや更新確認を追加した場合、CSP では検知できません。P12 のプロセス単位の監視が最終的な確認手段です。
| `SEC-011` | リリースビルドでは開発者ツールを無効化し、CSP でローカル同梱リソース以外へのナビゲーションとリモートオリジンへの通信を禁止する |
| `SEC-012` | Capability は必要最小限とし、フロントエンドへ任意パスのファイルアクセス権を与えない。読み取りは Rust コマンド経由に限定する |

## 起動手順の実装順序

入力資料 10.3 の「WebView2 Runtime の解決順序」をそのまま実装します。

1. `DIST-017` の設定を読む。Fixed Version の優先使用が指定されていれば手順 3 へ進む
2. 互換性のある導入済み Evergreen Runtime を確認する
3. 見つからない場合、実行ファイルと同じフォルダの `WebView2Runtime` を確認する
4. Fixed Version が見つかった場合、必要なフォルダ ACL を確認してから相対パスを指定する
5. 使用する Runtime が決まったら、ユーザーデータフォルダとして実行ファイル直下の `WebView2` を指定し、Tauri を初期化する。作成・書き込みできない場合は `DIST-014` に従い通知して終了する
6. どちらの Runtime も使用できない場合はネイティブダイアログで配置方法を通知し、Tauri を初期化せず終了する

手順 1 は設定ファイルの読み込みを必要とします。P03 の本格的な設定実装より前に、**`DIST-017`／`CFG-023` の1項目だけを読む最小の先行読み込み**が必要です。この先行読み込みで YAML が壊れていた場合は、`CFG-016` の安全モードへ入る判断を P03 側へ引き継ぎ、Runtime 解決は既定（自動判定）で進めます。

## 作業項目

1. **Evergreen Runtime の検出。** 導入済み Runtime の有無と、互換性のある版であるかを Rust 側で確認します。検出結果（使用した経路、版）を診断ログへ記録します（`DIST-017` の受け入れ条件が「使用中の Runtime を診断ログで確認できる」ことを求めています）。
2. **Fixed Version Runtime の使用。** `WebView2Runtime` フォルダを実行ファイルからの相対パスで解決し、`WEBVIEW2_BROWSER_EXECUTABLE_FOLDER` 相当をプロセス内で設定します。レジストリ登録とシステムフォルダ配置は行いません。
3. **フォルダ ACL の確認と設定。** `WebView2Runtime` フォルダだけを対象に、App Container 用の ACL が必要かを確認します。現在の権限で設定できる場合は設定し、できない場合は必要な権限と手順を通知します。**Runtime のインストールやシステム登録は行いません。**

   **`SEC-009` との関係を区別してください。** `SEC-009` は「実行時に作成・書き込みするフォルダを `logs`、`temp`、`WebView2` に限定する」と定めています。一方 `DIST-010` は `WebView2Runtime` フォルダの ACL 設定を許しています。両者は矛盾しません。

   | 区分 | 対象 | 可否 |
   | --- | --- | --- |
   | 実行時データの書き込み | `logs`、`temp`、`WebView2` | 許可（`SEC-009`） |
   | ACL（メタデータ）の変更 | `WebView2Runtime` フォルダのみ | **`DIST-010` による明示的な例外** |
   | Runtime のファイル内容の変更 | `WebView2Runtime` 配下のファイル | **行わない**（`DIST-011` により自動更新もしない） |
   | それ以外への書き込み | `%LOCALAPPDATA%` など | 行わない（`SEC-009`） |

   ACL 変更は実行時データの書き込みではなく、Runtime を使用可能にするための一回限りのメタデータ操作です。**ファイル内容は変更しません。** この区別を実装と検証の両方で保ちます。
4. **ネイティブダイアログによる通知。** Tauri を使わない通知経路を作ります。通知文には展開先を**絶対パス**で示します（10.3 の注記。`WebView2` と `WebView2Runtime` の取り違えを避けるため）。
5. **ユーザーデータフォルダの明示指定。** `WebView2` を実行ファイル直下に固定します。既定の `<実行ファイル名>.exe.WebView2` が作られないことを確認します。作成・書き込み不可の場合は理由、対象パス、必要な権限を通知して起動を中止し、別の場所へフォールバックしません。
6. **実行時フォルダの用意と清掃。** `logs` と `temp` を実行ファイル直下に用意します。起動時に `temp` の残存ファイルを清掃します（`SEC-006`、`PERF-016`）。`%LOCALAPPDATA%` などへは一切書きません。
7. **診断ログの実装。** `DIAG-005` の項目を記録できる形式にし、10 MiB × 5 世代のローテーションを実装します（設定値は P03 で `CFG-020` から読めるようにします）。マスキングは実装しません（`DIAG-003`、`DIAG-004`）。`logs` を作成・書き込みできない場合は理由を通知し、診断ログなしで動作を継続します。昇格プロセスの出力であることを判別できるようにします（`DIAG-007`）。
8. **Tauri のセキュリティ設定。** リリースビルドで開発者ツールを無効化し、CSP でローカル同梱リソース以外へのナビゲーションとリモートオリジンへの通信を禁止します。Capability を最小限に絞り、フロントエンドへ任意パスのファイルアクセス権を与えません。

## 影響

- **セキュリティ:** CSP と Capability の設定を緩めると、以降のフェーズすべての前提が崩れます。ただし**`SEC-001` はこのフェーズで完了しません**（下記）
- **データ:** `DIAG-003`・`DIAG-004` により、診断ログへ個人情報等の機密データが平文で出力され得ます。これは要件です。`logs` の閲覧制限、持ち出し、保管、削除は利用者・導入組織の責任範囲であり（`SEC-005`）、実装側で制限しません。**この方針を知らない読者が「情報漏えい」と誤認しないよう、診断ログの冒頭または文書へ明記してください**
- **性能:** ブートストラップの所要時間が起動時間に直接乗ります。Runtime 検出の実装方法によって差が出るため、所要時間を記録します
- **互換性:** `WebView2` フォルダの位置を後から変えると、既存の導入フォルダに残ったデータが孤立します。位置は `DIST-013` で固定されており変更しません

## リスクと未決事項

### 確定要件に起因するもの

- `DIST-010` の ACL 要否は「Windows 10 で必要な場合」という条件付きであり、**段階0では判明しない可能性があります**。要否の確定は P13（`VER-006`）です。段階0では「必要と判明したら設定を試み、できなければ通知する」経路を実装済みにしておきます
- `DIST-012` により、Evergreen 未導入端末では Runtime 追加パッケージの事前配置が起動の前提条件です。これは仕様上の既知の制約であり、実装で解消できません。導入手順書に反映する必要があります

### 暫定設計に起因するもの

- `DIST-017` の先行読み込みを、P03 の設定読み込みとどう共通化するかは設計判断です。二重実装になると、YAML の解釈が二か所に分かれる危険があります

### 人間判断待ち

- **Fixed Version WebView2 Runtime の入手が前提です。** 10.6 の暫定方針は、段階0で「Fixed Version Runtime を入手して `WebView2Runtime` へ配置し、`DIST-017` で強制使用した状態での起動確認」を行うと定めています。入手できないとこのフェーズの主目的（`VER-003`）が達成できません。**着手前に入手可否を確認してください**
- Evergreen の版差による挙動差が問題になる場合、`DIST-017` の既定を Fixed Version 固定へ変更する判断が入ります（10.4）。判断は P13 の結果を見てからです

## 完了ゲート

- Evergreen 経路、Fixed Version 経路、Runtime なしの3経路すべてが開発環境で確認できている
- Tauri を初期化できない状況でも、利用者が次に何をすればよいか分かる通知が出る
- 実行時の書き込み先が `logs`、`temp`、`WebView2` に限定されている
- 段階1で確認すべき事項が「LTSC・build 17763 固有の挙動」だけに絞られている
