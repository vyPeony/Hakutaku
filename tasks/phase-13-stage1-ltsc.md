# P13 段階1検証（LTSC 実機）と技術選定の確定

- 状態: 草案（Draft）
- 開始条件: P12 の完了ゲートを満たすこと。**Windows 10 IoT Enterprise LTSC 実機へのアクセスが確保できていること。他の業務ソフトウェアを稼働させられること**
- 前提フェーズ: P12
- 段階: **段階1**（検証ゲート。実装フェーズではありません）
- 期待成果物: `ENV-001` の下限ビルドの確定、Evergreen 未導入環境での起動確認、他の業務ソフトウェア稼働中の性能実測、`PERF-014` の既定値、`DEC-002` の確定
- 予定変更範囲: 検証記録、ADR（`DEC-002` の確定）、`CFG-024` の既定値、要件文書の `ENV-001`

## 目的

LTSC 実機で、段階0では確認できなかった事項を検証します。**このフェーズの完了をもって `TECH-003`（Rust＋Tauri）を確定します**（`VER-001`、`DEC-002`）。

10.6 は、このフェーズを分けた理由を述べています。

> LTSC 実機へのアクセスが一定期間確保できないため、検証を段階0（現行の開発環境）と段階1（LTSC 実機）に分ける。段階0を先行させる一方で、**LTSC でのみ露見する問題を段階0の設計判断で作り込まないための制約**を併せて定める。

段階0で `VER-003`（Evergreen 非依存）と `VER-004`（ビルド下限）を守っていれば、このフェーズで新たに確認が必要なのは次の三つに絞られます。

1. LTSC というエディション固有の挙動
2. build 17763 固有の挙動
3. 他の業務ソフトウェアとの同時稼働

## 最重要項目

10.4 の暫定方針は、優先順位を明示しています。

> **段階1の最重要項目は、対象機種のうち最も古い Windows 10 IoT Enterprise LTSC の実機での起動確認**である。Edge および Evergreen WebView2 Runtime が存在しない状態から、Fixed Version Runtime を `WebView2Runtime` へ展開しただけで起動できることを確認する。**ここが成立しないと `TECH-003`（Tauri 採用）の前提が崩れる。**

したがって、この確認を最初に行います。成立しない場合、以降の検証より先に技術選定の再検討が必要です。

## 作業項目

1. **最古機種での起動確認（最重要）。** Edge および Evergreen Runtime が存在しない状態から、Fixed Version Runtime を `WebView2Runtime` へ展開しただけで起動できることを確認します。
   - **成立しない場合、以降の検証を進める前に `DEC-002` の見直しを検討します**
2. **`ENV-001` の下限確定。** 最も古い機種のビルド番号を実測し、`ENV-001` の下限を確定します。段階0では「1809 / build 17763 相当と想定」でした。
3. **Evergreen 導入済み機種での確認。** 両経路が成立することを確かめます（`ENV-008`）。機種により Evergreen の版が異なるため、**版差による描画・挙動の差異が問題になるかを確認します**。
   - 問題になる場合、`DIST-017` による Fixed Version 固定を**既定へ変更する**ことを検討します（10.4）
4. **フォルダ ACL の要否確定。** `WebView2Runtime` フォルダに App Container 用の ACL が必要かを実測します（`DIST-010`）。
5. **`WebView2` フォルダの作成可否。** 実機で作成・書き込みできることを確認します（`DIST-013`）。できない場合の通知（`DIST-014`）も確認します。
6. **他の業務ソフトウェア稼働中のログ読み取り。** **対象となるログファイル全種について読み取れることを実測確認します**（`LOG-027`、`Q-038`）。
   - 稼働中にメモ帳で開けた実績があるため成立する見込みですが、**ファイル種別や動作局面によって共有モードが異なる可能性**を確認します
   - 読み取れないファイル種別が見つかった場合、`LOG-027` の共有違反経路が正しく動作することを確認します
7. **他の業務ソフトウェア稼働中の性能測定。** 稼働している状態と稼働していない状態の双方で測定し、両方の実測値を記録します（`PERF-015`）。
   - **合否は他の業務ソフトウェア稼働中の値を基準とします**
   - 開発用 PC での測定値は参考値であり、合否判定に使いません（5.4）
8. **他の業務ソフトウェアへの影響確認。** 1 GB のログを読み込んでも、他の業務ソフトウェアの動作に体感できる影響が出ないことを確認します。影響が出る場合、同時実行数・I/O 間隔・プロセス優先度の設定で抑制できることを確認します（`PERF-014`）。

   **「体感できる影響」を合否に使うため、試験前に判定手順を固定します。** `PERF-009` が禁じているのは一律の合格秒数であり、シナリオ固有の判定手順は禁じていません。次を着手可能（`Ready`）な Issue へ書き込んでから測定してください。

   | 固定する項目 | 内容 |
   | --- | --- |
   | 観測項目 | 他の業務ソフトウェア側の何を見るか（画面更新の間隔、操作応答、内部の処理時間、エラーの発生など） |
   | 対象操作 | 他の業務ソフトウェアのどの操作を、どの順で、何回行うか |
   | 評価者 | 誰が判定するか。**他の業務ソフトウェアの通常動作を知る人が必要です** |
   | 停止条件 | どの状態になったら試験を中止するか（他の業務ソフトウェアのエラー、対象端末の異常など） |
   | 比較基準 | Hakutaku を動かしていない状態の同じ操作 |

   これを固定せずに測ると、「体感できる影響」の判断が測定ごとに変わり、合否が再現しません。

9. **`PERF-014` の既定値決定。** 対象端末での実測に基づき、`CFG-024` の既定値を確定します。

   **既定値の変更には再ビルド・再配布・再測定のループが伴います。** 既定値は設定ファイルではなく組み込み値であるため（`CFG-015` により設定ファイルなしでも起動する必要があります）、変更するたびに次を繰り返します。

   1. 既定値を変更して再ビルド
   2. 配布物を作り直して実機へ再配置
   3. 他の業務ソフトウェア稼働中の測定をやり直す

   この往復を見込んで日程を確保してください。設定ファイルで値を変えながら探索し、**最後に決めた値を既定へ入れて1回だけ確認する**進め方を推奨します。
10. **安全な停止の確認。** 読み込み中に強制終了しても、参照対象と他の業務ソフトウェアの動作に影響が出ないことを確認します（`PERF-016`）。
11. **セキュリティソフトの影響評価。** エンタープライズ向けセキュリティソフトが稼働する環境での実測を含めます（`PERF-009`、5.4）。
12. **`DEC-002` の確定。** 上記が成立した場合、ADR の状態を暫定決定から決定へ変更します。

## 影響

- **セキュリティ:** 実機で稼働する他の業務ソフトウェアが扱うデータは個人情報等の機密データを含み得ます。**検証記録に実データを含めません。** ログ種別の名称と読み取り可否だけを記録します
- **データ:** 実機の参照対象を変更しないことを、読み込み前後のハッシュとタイムスタンプで確認します
- **性能:** このフェーズの実測値が**唯一の合否判定基準**です（`PERF-015`）。段階0の値は参考値です
- **互換性:** `ENV-001` の下限がここで確定します。確定後に下限を上げる変更は、対象機種を切り捨てることになるため行いません

## リスクと未決事項

### 確定要件に起因するもの

- **最古機種での起動が成立しない場合、`TECH-003`（Tauri 採用）の前提が崩れます。** 10.4 が明示している最大のリスクです。この場合、GUI フレームワークの再選定が必要になり、段階0の成果のうち GUI 層が影響を受けます。10.6 の暫定方針が「GUI 層と Rust コア層の境界を明確に保つ」ことを求めているのはこの備えです
- **`LOG-027` は保証ではありません。** 読み取れないログ種別が実測で見つかる可能性があります。その場合、共有違反経路（実装済み）で対応し、当該ログ種別が調査対象から外れることを利用者と確認する必要があります
- **`PERF-015` により、合否は他の業務ソフトウェア稼働中の値が基準です。** 段階0で良好だった値が、対象端末では許容できない可能性があります。その場合、`PERF-014` の抑制を強めるか、設計の見直しが必要です

### 暫定設計に起因するもの

- 「段階1で新たに確認が必要なのは LTSC・build 17763 固有の挙動と他の業務ソフトウェアとの同時稼働に限定できる」という 10.6 の見込みが正しいかは、このフェーズで判明します
- Evergreen の版差が問題になる場合の対応（`DIST-017` の既定変更）は 10.4 の暫定方針です

### 人間判断待ち

- **LTSC 実機へのアクセス確保が前提です。** 10.6 は「LTSC 実機へのアクセスが一定期間確保できない」ことを理由に段階を分けたと記録しています。アクセスの見通しを確認してください
- **他の業務ソフトウェアを稼働させた状態での検証許可が必要です。** 対象端末上で調査ツールを動かすことになります
- Evergreen 未導入の最古機種と、Evergreen 導入済み機種の**両方**が必要です（`ENV-008`）
- セキュリティソフトが稼働する環境の確保方法が未決です

## 完了ゲート

- 最古機種での Fixed Version 起動が成立している
- `ENV-001` の下限ビルドが確定している
- 両経路（Evergreen／Fixed Version）が実機で成立している
- 対象ログ全種の読み取り可否が実測されている
- 他の業務ソフトウェア稼働中の性能値が記録され、他の業務ソフトウェアへの影響が許容範囲である
