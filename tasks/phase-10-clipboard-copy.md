# P10 選択とクリップボードコピー

- 状態: 草案（Draft）
- 開始条件: P08 の完了ゲートを満たすこと。P02 の予約経路と P03 の `CFG-018` が利用できること
- 前提フェーズ: P08
- 段階: 段階0
- 期待成果物: 行・セル範囲の選択、`Ctrl+C` でのコピー、上限判定と拒否、タブ・改行区切りのプレーンテキスト出力
- 予定変更範囲: GUI 側の選択とコピー操作、コア側のコピー用バッファ生成と上限判定

## 目的

ビューア上の選択範囲を Windows のクリップボードへコピーできるようにします。

`COPY-003` により、クリップボードコピーはファイルエクスポートとは区別され、**初期リリースから提供します**（検索結果のファイルエクスポートは `LOG-019` により不要です）。

## 上限の扱い（誤解しやすい点）

`COPY-005` は**部分コピーを禁止**しています。

> 選択範囲が上限を超える場合は部分コピーを黙って行わず、コピー全体を拒否して上限と選択量を表示する。

上限に収まる分だけをコピーする実装は要件違反です。クリップボードを変更せずに拒否します。上限は「UTF-8 換算 16 MiB **または** 10 万行のうち先に到達した方」です（`COPY-004`）。

**境界の扱いに注意してください。** `COPY-005` は「上限を**超える**場合」に拒否と定めています。したがって **16 MiB ちょうど、10万行ちょうどは許可**です。「到達したら拒否」と実装すると、境界がひとつずれます。

## 対象要件

| ID | 要求の要旨 |
| --- | --- |
| `COPY-001` | ビューア上に表示された行またはセル範囲を選択できる |
| `COPY-002` | 選択範囲を `Ctrl+C` で Windows のクリップボードへコピーできる |
| `COPY-003` | クリップボードコピーはファイルエクスポートと区別し、初期リリースから提供する |
| `COPY-004` | 1回のコピー上限は、UTF-8 換算 16 MiB または10万行のうち先に到達した方。上限値は設定で変更可能 |
| `COPY-005` | 上限を超える場合は部分コピーを黙って行わず、コピー全体を拒否して上限と選択量を表示する |
| `COPY-006` | 機密情報または個人を識別し得る情報が含まれ得ることを前提とし、コピーは明示的なユーザー操作時だけ行う |
| `PROD-013` | ビューア上の選択範囲を `Ctrl+C` でクリップボードへコピーできる |
| `CFG-018` | コピーの最大バイト数と最大行数を設定できる。初期値 16 MiB、10万行 |
| `SEC-004` | コピーはユーザーが明示的に実行した場合だけ行う。**初期リリースでは「明示的な操作時のみコピーする」ことだけを適用範囲とする** |
| `PERF-008`／`PERF-010` | コピー用バッファの確保を予約経路へ通す |
| `LOG-024` | 原文を失わない |

## 作業項目

1. **選択の実装。** 行単位およびセル範囲の選択を提供します。仮想スクロールと組み合わせるため、**表示されていない範囲を含む選択**（全選択、範囲指定）の扱いを決める必要があります。
2. **上限判定。** 選択量を UTF-8 換算バイト数と行数で算出し、`CFG-018` の上限と比較します。**どちらかが上限を超えた場合に拒否します。**
   - **上限値ちょうどは許可です。** `COPY-005` は「選択範囲が上限を**超える**場合は…拒否」と定めています。16 MiB ちょうど、10万行ちょうどはコピーできます
   - 境界のテスト（上限ちょうど、上限 +1 バイト、上限 +1 行）を必ず入れてください
3. **拒否時の表示。** 上限値と選択量を表示します。**クリップボードを変更しません。**
4. **コピー内容の生成。** 5.2 の暫定方針に従い、**上限判定後に必要なバッファをメモリ予算へ予約してから生成します**。バックグラウンドで自動生成しません。
   - 表形式の複数セルは、一般的な表計算ソフトへ貼り付けやすい**タブ区切り・改行区切りのプレーンテキスト**とします
   - ログ原文に複数行が含まれる場合も、その内容を失いません（`LOG-014` の論理ログ項目）

### 原文にタブ・改行が含まれる場合（推奨案）

`LOG-024`（原文を失わない）と、表計算ソフトへの貼り付け（4.5 の暫定方針）が競合する箇所です。次を推奨案として記録します。

**`LOG-024` は「原文を内部で保持し、表示から確認できる」要件です。** すべてのコピー出力を無加工の文字列にすることまでは求めていません。したがって、**選択の種類で出力形式を分けます**。

| 選択の種類 | 出力 |
| --- | --- |
| 行または論理ログ項目の選択 | **原文をそのままコピーする。** 内部のタブ・改行を保持する |
| セル範囲の選択 | **可逆な quoted TSV。** タブ、改行、二重引用符を含むセルを二重引用符で囲み、セル内の二重引用符を重ねる |

**バックスラッシュによる `\t` / `\n` への置換は採りません。** 元のバックスラッシュ列と区別できず、可逆でないためです。ログ本文にはパスなどバックスラッシュを含む文字列が頻繁に現れます。

対象の表計算ソフトが quoted TSV を直接貼り付けできない場合は、**Windows の HTML Clipboard 形式を同時に載せ、Unicode プレーンテキストを代替（fallback）にする**案が安全です。

コピー上限（`COPY-004`）は**正準のプレーンテキストの UTF-8 換算**で判定します。複数形式を載せる場合、**生成するすべての Clipboard 形式のバッファをメモリ会計へ載せます**（`PERF-008` はコピー用バッファを予算対象に含めています）。

これは利用者の作業手順に直接影響するため、**人間判断で確定させてください**。
5. **明示的な操作に限定。** 選択の変更やスクロールでクリップボードを書き換えません（`COPY-006`、`SEC-004`）。
6. **メモリ会計への接続。** コピー用バッファを P02 の予約経路へ通します。上限が 16 MiB であるため、予算 2 GB に対しては小さいものの、`PERF-008` は「コピー用バッファ」を明示的に予算対象へ含めています。

## 影響

- **セキュリティ:** **コピーは個人情報等の機密データがほかのアプリへ渡る経路です。** `COPY-006` により明示的な操作時だけに限定します。初期リリースでは通知を出しません（`SEC-004` の適用範囲は「明示的な操作時のみコピーする」ことだけ）
- **データ:** 参照元への影響はありません
- **性能:** 上限が 16 MiB であるため影響は限定的です。ただし 16 MiB のテキスト生成は一定の時間がかかるため、UI を止めない実装が必要です
- **互換性:** コピー形式（タブ・改行区切り）は利用者の作業手順に組み込まれます。後から変えると貼り付け先の処理が壊れる可能性があります

## リスクと未決事項

### 確定要件に起因するもの

- **表示外の範囲を含む選択の扱いが未決です。** 仮想スクロールでは表示されていない行の内容を保持していません（`PERF-012`）。全選択や広範囲選択に対して、コア側から再取得して量を算出する必要があります。上限（10万行）を超える選択が拒否されるため、**上限を超える選択でも「量の算出」だけは行える設計**が必要です
- `COPY-004` の「UTF-8 換算 16 MiB」は、表示中の文字コードではなく UTF-8 に変換した後のバイト数です。ANSI で読み込んだログをコピーする場合、換算が必要です

### 暫定設計に起因するもの

- タブ区切り・改行区切りのプレーンテキストという形式は 4.5 の暫定方針です。要件は「表計算ソフトへ貼り付けやすい」ことまでを求めています
- 「上限判定後に必要なバッファをメモリ予算へ予約してから生成する」順序も暫定方針です

### 人間判断待ち

- 表形式のセル選択において、原文に**タブ文字や改行が含まれる場合の扱い**が未決です。上記「原文にタブ・改行が含まれる場合（推奨案）」に方針を記録しました。利用者の作業手順に直接影響するため、**人間判断で確定させてください**
- 複数の Clipboard 形式（HTML Clipboard 形式と Unicode プレーンテキスト）を載せるかも判断が必要です。対象の表計算ソフトが quoted TSV を扱えるかに依存します

## 完了ゲート

- 上限内のコピーが成功し、上限超過が部分コピーなしで拒否される
- 拒否時に上限値と選択量が分かる
- 複数行原文がタブ・改行区切りで失われずにコピーされる
- 明示的な操作以外でクリップボードが変更されない
