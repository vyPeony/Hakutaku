## B. SQLite ビューア

| ID | 要求の要旨 |
| --- | --- |
| `DB-001` | SQLite を、論理的内容を変更しない読み取り専用接続で開く。**他の業務ソフトウェアが使用中の DB へ接続するケースを標準ケースとして扱う** |
| `DB-003` | GUI 操作で任意のテーブルを選び、内容を表示できる |

| `DB-005` | 別テーブルの内容へタブなどで切り替えられる |
| `DB-006` | データベースの論理的内容およびスキーマを編集しない |
| `DB-007` | 最初の実装では、選択したテーブルの全レコードを閲覧対象とする。並べ替え、検索、絞り込みは必須としない |
| `DB-009` | 他プロセスの排他ロックにより開けない場合、ロックを強制解除せず理由を表示する |
| `DB-010` | BLOB 列は、最初の実装では BLOB であることとバイトサイズだけを表示する |
| `DB-011` | 現時点のデータベース対応では認証情報を扱わない |
| `DB-012` | WAL モードで、SQLite ライブラリが必要とする `-wal`、`-shm` の作成・アクセス・更新を許容する |
| `DB-013` | WAL モードで、必要な付随ファイルがなく DB ディレクトリにも書き込めない場合、読み取り専用接続に失敗し得ることを既知の制約とする |
| `DB-014` | 使用中または変更される可能性がある DB に `immutable=1` を自動適用しない。初期実装では使用しない |
| `DB-008` | SQLite ビューアの第2段階では、レコードの検索・絞り込みを検討対象とする |

### 注意点

**「読み取り専用」の意味が SQLite では特殊です。** 入力資料の第1章が定義しています。

> SQLite は読み取り専用接続を使用するが、WAL モードの同時参照に必要な SQLite 管理下の付随ファイル（`-wal`、`-shm`）については、SQLite ライブラリによる作成、アクセスまたは更新を許容する。このため、SQLite については参照元ディレクトリへのファイルシステム上の書き込みが一切発生しないことまでは保証しない。

**論理的内容を変更しないこと**と、**付随ファイルへの書き込みが発生し得ること**を区別してください（`DB-012`）。`immutable=1` は使用中の DB に誤適用すると不正な結果や破損扱いのエラーを招くため、初期実装では使いません（`DB-014`、`DEC-024`）。

### 転送構文の対応範囲

| ID | 対応範囲 |
| --- | --- |
| `DCM-TS-001` | DICOM Part 10 ファイルを対象とし、128バイトの File Preamble、`DICM` Prefix、File Meta Information があるファイルを受け付ける。Part 10 ヘッダーのない生の Data Set は対象外 |

## E. 索引キャッシュ

| ID | 要求の要旨 |
| --- | --- |
| `CFG-011` | **索引キャッシュは初期リリースでは提供しない。** 後続リリースで提供する場合は、設定で ON/OFF でき、既定値を OFF とする |
| `CFG-012` | 提供する場合、保存内容、保存期間、容量に運用制約を設けない。ログ本文、DB セル値、DICOM タグ値を平文で保存してよく、暗号化、アクセス制御、保持期限、自動削除のいずれも要件としない。削除は利用者による手動操作のみ |
| `CFG-021` | 索引キャッシュは対象ファイルの指紋（サイズ、最終更新時刻、先頭・末尾の部分ハッシュ）と対応付けて保存する。読み込み時に指紋を照合し、一致しない場合はキャッシュを使用せず破棄して索引を再構築する。指紋を照合できない場合もキャッシュを使用しない。**この要件を満たせない実装でキャッシュを提供してはならない** |
| `SEC-002` | 提供する場合は既定 OFF とし、保存内容と形式に制約を設けず、暗号化とアクセス制御は要件としない |
| `SEC-003` | 削除は利用者による手動操作のみ。GUI からキャッシュを消去できる機能は**望ましい要件** |
| `SEC-008` | 提供する場合も暗号化、アクセス制御、保持期限、自動削除は行わない |

### 追加を検討する条件

`DEC-043` は初期リリースから除外した理由を記録しています。

> 既定 OFF で効果が未計測である一方、`CFG-021` の指紋照合を誤ると「別ファイルの内容を正しそうに表示する」故障につながり、テスト分岐も増えるため。

したがって、**初回表示時間の実測（P13）が許容できない場合に限り**、後続リリースで追加を検討します（5.2）。

### 最重要の注意点

**`CFG-021` は「この要件を満たせない実装でキャッシュを提供してはならない」と明示しています。** 保存内容に制約を設けないこと（`CFG-012`）と、保存した索引が元ファイルと一致していることの保証は**独立した論点**です（`DEC-041`）。指紋照合を実装しないままキャッシュを提供することは要件違反です。

提供する場合の既定は `cache.enabled: false`、既定保存先は実行ファイル直下の `cache`（`SEC-009`）、特別な ACL は付与しません。

## リスクと未決事項

### 確定要件に起因するもの

- `DB-013` の既知の制約（WAL モードで付随ファイルがなく DB ディレクトリも書き込み不可の場合、読み取り専用接続に失敗し得る）は実装で解消できません。利用者向け説明が必要です
- `DCM-TS-003` により未対応の転送構文があります。実データに含まれる場合、対応範囲の見直しが必要です。Explicit VR Big Endian は DICOM 標準上で廃止済みですが、実データ要件が判明した場合は追加対応を検討します
- `CFG-021` の指紋照合を実装できない場合、キャッシュを提供できません

### 暫定設計に起因するもの

- `6.3` のプライベートタグ解析スキーマは仮案 v1（`DEC-045`）であり、実データでの試作結果により改訂します
- 複数ファイルのタグ比較を「タグを行、DICOM ファイルを列とする比較表」とするのは 6.2 の第一案です

### 人間判断待ち

- **各項目の着手順が未決です。** 12.2 により「各後続リリースの計画時に決定する」とされています
- SQL Server の再検討条件（対象バージョン、認証方式など）が判明していません
- 索引キャッシュを追加するかは、P13 の初回表示時間の実測を見た判断です
