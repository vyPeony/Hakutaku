# P03 設定ファイル `hakutaku.yaml`

- 状態: 草案（Draft）
- 開始条件: P01（診断ログ、実行時フォルダ）と P02（予算値の受け取り口）の完了ゲートを満たすこと
- 前提フェーズ: P01、P02
- 段階: 段階0（`VER-007` により設定スキーマは段階0で確定してよい）
- 期待成果物: `hakutaku.yaml` の読み込みと起動時検証、正常／既定値／安全モードの3経路、各フェーズへの設定値の受け渡し
- 予定変更範囲: コア側の設定クレート、GUI 側の安全モード表示、`hakutaku.yaml` の記述例

## 目的

実行ファイルと同じフォルダの `hakutaku.yaml` を読み込み、起動時に全体を検証し、不正な設定を黙って既定値へ置換せずに安全モードで起動する仕組みを作ります。

`VER-007` は「設定スキーマは段階0で確定してよい」と定めています。実機を待つ必要がないため、この段階で構造を固めます。以降のフェーズは、それぞれが必要とする設定項目をこの土台へ追加する形になります。

### このフェーズが確定させるもの／させないもの

**このフェーズは「設定基盤と共通スキーマの確定」です。** 設定値を実際に使う挙動の確認は、各消費フェーズが持ちます。

| 区分 | 内容 | 所有 |
| --- | --- | --- |
| 設定基盤 | 読み込み、3つの起動経路、起動時検証の枠組み、行・列付きエラー、`config_version` | **P03** |
| 共通スキーマ | 区分の構造、共通設定の各項目、型と値域、消費側への受け渡し | **P03** |
| ログ解析プロファイルのスキーマの**形** | 項目名、型、`encoding`／`ansi_codepage` の位置 | **P03** |
| ログ解析プロファイルの**意味検証** | 同優先度 glob の重複検出、パス正規化規則、解決順の妥当性 | **P05** |
| 各設定値を使った**挙動** | コピー上限の適用、保持上限の適用、抑制の適用 | P10、P08、P11 |

P03 の受け入れ条件は「型付きの値として検証し、消費側へ受け渡せる」までです。**「設定を変えたら挙動が変わる」ことは P03 単独では確認できません**（消費側が未実装のため）。各消費フェーズの受け入れ条件で確認します。

ログ解析プロファイルの意味検証を P05 が持つのは、検証規則が解決アルゴリズムと不可分だからです。P03 はスキーマの形と汎用的な構文・型検証までを確定させ、**プロファイル固有の意味検証を後から追加できる形にしておきます**。これは P03 の完了ゲート違反ではありません。

## 設定の三つの起動経路

`CFG-015` と `CFG-016` は異なる経路であり、混同しないでください。

| 経路 | 条件 | 挙動 | 要件 |
| --- | --- | --- | --- |
| 正常起動 | `hakutaku.yaml` があり、構文と値が妥当 | 設定を適用して起動 | — |
| 既定値起動 | `hakutaku.yaml` が**存在しない** | 組み込み既定値で起動する。アドホックなファイル選択は利用できる。設定未検出を**非致命的な通知**として表示する | `CFG-015` |
| 安全モード | `hakutaku.yaml` が**存在するが構文または値が不正** | 誤設定を黙って既定値に置換しない。UI は起動するが、設定由来のデータソース、プロファイル、キャッシュを**無効化**し、ファイル名・行・列・理由を表示する | `CFG-016` |

いずれの経路でも、**アプリが設定ファイルを自動生成または上書きすることはしません**（8.2）。設定ファイルはショートカット、既定値、解析プロファイルを提供するものであり、アドホックなファイル選択の前提条件ではありません（`CFG-017`）。

## 作業項目

1. **設定の区分。** 8.2 に従い、共通設定、データソース、ログ解析プロファイルに分けます。DICOM プライベートタグ解析規則と DB 接続定義は後続リリースの区分として**構造上の場所だけを想定**し、初期リリースでは実装しません。
2. **形式バージョンの導入。** `config_version` を持たせ、将来の構造変更時に明確なエラーまたは移行案内を出せるようにします（8.2、`6.3.6` の記述例に `config_version: 1` があります）。
3. **絶対パスの検証。** 読み込み対象のパスを絶対パスとして検証します。相対パスやネットワーク共有パスが指定された場合の扱いは未決です（下記「人間判断待ち」）。`CFG-016` は「誤設定を黙って既定値に置換しない」ことを求めるため、**少なくとも黙って無視することはできません**。
   - パスの正規化規則そのもの（大文字・小文字の扱い、区切りの統一）は P05 のプロファイル照合と共通です。**P03 で正規化の実装を置き、P05 が照合規則として利用します。**
4. **起動時検証の実装。** 設定全体を起動時に検証し、誤りのあるファイル名、項目、**行・列**、理由をユーザーへ示します。行・列を出すには YAML パーサーが位置情報を保持する必要があり、**パーサー選定時の必須条件**です。
5. **安全モードの実装。** 検証に失敗した場合、UI 自体は起動しつつ、設定由来のデータソースとプロファイルを無効化します。この状態でもアドホックなファイル選択は利用できます（`CFG-017`）。
6. **既定値起動の実装。** 設定ファイルがない場合、組み込み既定値で起動し、非致命的な通知を表示します。**ファイルを自動生成しません。**
7. **各フェーズへの設定値の受け渡し。** `CFG-007`（P02）、`CFG-018`（P10）、`CFG-020`（P01）、`CFG-022`（P08）、`CFG-023`（P01）、`CFG-024`（P11）を、各フェーズが読める形で提供します。
8. **ログ解析プロファイルのスキーマ。** `CFG-008` の `encoding` と `ansi_codepage` を含む構造を定義します。プロファイルの意味解釈と照合は P05 ですが、**スキーマの形はここで確定します**（`VER-007`）。設定例は 4.3 にあります。

```yaml
config_version: 1

log_profiles:
  - name: japanese_sample_log
    path_pattern: "C:/Logs/*.log"
    encoding: auto
    ansi_codepage: 932
```

9. **`DIST-017` の先行読み込みとの統合。** P01 が `CFG-023` だけを先読みしています。YAML の解釈が二か所に分かれないよう、共通の読み込み口へ寄せます。

## 影響

- **セキュリティ:** `CFG-013` により認証情報の項目を作りません。将来 SQL Server 対応を追加する場合、平文保存しない方式を改めて検討します（8.2）
- **データ:** 設定ファイルを読み取り専用として扱います。自動生成・上書きをしないため、利用者の設定が失われません
- **性能:** 起動時に設定全体を検証するため、起動時間へ加算されます。設定は小さいため影響は限定的と見込みますが、測定対象に含めます
- **互換性:** `config_version` により将来の構造変更に備えます。スキーマの形はここで確定し、以降のフェーズは項目の追加のみ行います

## リスクと未決事項

### 確定要件に起因するもの

- **YAML パーサーが行・列の位置情報を保持する必要があります。** `CFG-016` の受け入れ条件が行・列の表示を求めているため、位置情報を持たないパーサーは選定できません。選定を誤ると後から差し替えになります
- `CFG-022` の初期値は「技術試作の実測により決定する」と定められており、P04 の結果を待ちます。P03 では設定項目と暫定既定値を置き、P04 で確定させます

### 暫定設計に起因するもの

- 設定の区分（共通設定 / データソース / ログ解析プロファイル）は 8.2 の暫定方針です。後続リリースで DICOM と DB の区分を足す際に見直しになり得ます
- `config_version` の運用（どの変更で上げるか）は `14.1` の更新ルールに準じますが、実装上の判定基準は決まっていません

### 人間判断待ち

- **`CFG-010` の相対パス・ネットワーク共有パスの扱いが未決です。** `CFG-010` は「対応不要」、8.2 は「動作保証は行わない」としており、起動時検証でエラーにするか、警告して続行するかを決めていません。`CFG-016` により黙って無視はできません。**着手時に決めて ADR へ記録してください**
- `CFG-024` の既定値は「対象端末での実行を前提に控えめに定める」とされていますが、具体値は P13（`VER-006`）で決めます。段階0では控えめな暫定値を置きます

## 完了ゲート

- 3つの起動経路すべてが確認でき、誤設定が黙って既定値に置換される経路が存在しない
- **設定基盤と共通スキーマ**が確定し、以降のフェーズが項目追加だけで済む状態（`VER-007`）
- 各フェーズが必要な設定値を型付きの値として受け取れる状態

ログ解析プロファイルの意味検証（同優先度 glob の重複検出など）は P05 の完了ゲートです。このフェーズのゲートには含めません。
