# P08 ログ表示と仮想スクロール、保持上限の運用

- 状態: 草案（Draft）
- 開始条件: P06（索引と範囲取得）と P07（共通シェル）の完了ゲートを満たすこと
- 前提フェーズ: P06、P07
- 段階: 段階0
- 期待成果物: 大規模ログの仮想スクロール表示、原文と解析結果の併記、未確定行の区別表示、`PERF-012` の保持上限の運用、ファイル別タブの表示
- 予定変更範囲: GUI 側のログビュー、範囲取得の呼び出し、保持上限と破棄の実装

## 目的

P04 で契約を確定させた範囲取得と保持上限を、実際の規模で運用できる表示に仕上げます。

P04 との違いは**規模と作り込み**です。P04 は「契約が成立するか」を確かめる最小構成でしたが、このフェーズは 1 GB・複数ファイル・10万行超という実際の条件で、原文の保持、解析結果の列表示、未確定行の区別、保持上限の運用を成立させます。

### P04 との担当境界

- **P04 が所有するもの:** 範囲取得契約、保持上限、破棄・再取得の成立
- **このフェーズが行うこと:** **その契約を変更せず**、仮想表示の完成度と連続スクロール検証の水準を上げる

契約の変更が必要になった場合、黙って変えずに契約変更として扱ってください。P04 の「契約に織り込む4点」（表示集合に対する範囲取得、安定した識別子と来歴、再取得時の決定性、世代による無効化検出）は、このフェーズでも維持します。

## 対象要件

| ID | 要求の要旨 |
| --- | --- |
| `LOG-001` | テキスト形式のログファイルを読み込める |
| `LOG-015` | 統合表示が OFF の場合はファイル別タブで表示を切り替える。分割表示は不要 |
| `LOG-024` | 解析した日時には元の精度を保持し、**表示時に失わない** |
| `LOG-026` | 書き込み途中の可能性がある未確定行として**区別して表示する** |
| `LOG-004` | ログレベルが存在しない形式も扱える（列がない場合の表示） |
| `PERF-012` | 可視範囲と前後の一定バッファに限って行データを保持し、取得済みの行を累積しない。上限超過時は遠い範囲を破棄し、必要時に再取得する |
| `PERF-013` | `PERF-008` の予算ではフロントエンドの累積を検知できない。`PERF-012` の上限を一次的な歯止めとする |
| `CFG-022` | フロントエンドが保持する行数・バイト数の上限を設定できる（初期値は P04 で決定） |
| `PERF-007` | 10万行超を性能試験条件に含める |
| `ENV-005` | 1920×1080 を基準とする |
| `PROD-015`／`ENV-007` | 日本語のみ |
| `PERF-014` | 対象端末で他の業務ソフトウェアの動作を阻害しない（表示側の先読み量に影響） |

## 作業項目

1. **仮想スクロールの本実装。** 索引を使い、任意の位置へジャンプできるようにします。可視範囲と前後の一定バッファのみを保持します。
2. **保持上限の運用。** `CFG-022` の行数・バイト数上限を適用します。上限を超えた場合、表示範囲から遠い範囲を破棄し、スクロールで戻った際に再取得します。
   - **`PERF-013` により、この上限がフロントエンド側メモリの唯一の歯止めです。** 上限を無効化する経路を作らないでください
   - **上限の対象は自前のキャッシュだけではありません。** `PERF-012` は「フロントエンドが保持する行データ」全体に適用されます。表示ライブラリ内部の行モデル・キャッシュ、DOM が保持する行参照、購読・イベントハンドラーが保持する行参照を含めて、上限を守る設計にしてください
   - 第三者ライブラリ内部を直接数えられない場合は、行モデルの生成・解放計数、DOM ノード数、購読解除の検証、必要に応じた heap snapshot を組み合わせて確認します
3. **原文と解析結果の併記。** 表示では原文を失わず、解析済みの項目（日時、ログレベルなど）は列や色分けに利用します（4.1）。
   - **日時は元の精度で表示します。** `15:12` を `15:12:00.000` に書き換えて見せません（`LOG-024`）
   - 日時表示の書式を正規化する場合も、原文を別途確認できるようにします（4.2）
4. **論理ログ項目の表示。** 日時付き行と継続行を一つの項目として、改行を保って表示します（`LOG-014`）。
5. **未確定行の区別表示。** 末尾の断片を「書き込み途中の可能性がある未確定行」として区別します。**解析エラーの表示と区別します**（`LOG-026`）。
6. **日時未解析の生表示。** `LOG-022` で自動判定に失敗した場合、および日時なしで始まるファイル先頭の行を、日時未確定の生データとして表示します。
7. **ログレベルのない形式への対応。** ログレベル列が存在しない形式でも表示が崩れないようにします（`LOG-004`）。
8. **ファイル別タブ。** 統合表示 OFF 時に、ファイル単位でタブを切り替えます。分割表示は作りません（`LOG-015`）。
9. **先読み量の抑制。** 対象端末での実行を前提に、先読みを控えめにします。`PERF-014` の抑制設定と連動させます（設定は P11）。
10. **解放対象の登録。** 表示範囲のキャッシュを、P02 のソフトしきい値到達時に解放する対象として登録します。

## 影響

- **セキュリティ:** 表示されたログ本文は `WebView2` フォルダへ残留し得ます（`SEC-010`）。導入フォルダごと処分できる状態を保つことが対応です
- **データ:** 表示切り替えや再取得で参照元を変更しません（`ERR-003`）
- **性能:** **このフェーズがスクロール応答性の中心です。** P04 で決めた転送経路と保持上限が、ここで実規模の負荷にかかります。段階0の値は参考値ですが（`VER-005`）、回帰の基準として記録します
- **互換性:** 表示の内部構造は P09（統合表示）と P10（コピー）が依存します

## リスクと未決事項

### 確定要件に起因するもの

- **`PERF-012` の保持上限は、実装が容易に破れます。** 表示ライブラリの内部キャッシュ、DOM ノードの保持、イベントハンドラーの蓄積などが原因になり得ます。P04 で確認済みでも、作り込みで再発する可能性があるため、このフェーズでも**内部状態で再確認します**
- 段階0では、機能の判定を**内部状態**で行い、プロセスのメモリ量では行いません（`VER-005`）。メモリ推移の傾向値の判定は P13 です
- `LOG-024` の「表示時に精度を失わない」と、4.2 の「日時表示の書式を正規化しても原文は別途確認可能にする」を両立させる必要があります。列の設計で解決してください

### 暫定設計に起因するもの

- 列構成、色分け、未確定行の見せ方はすべて設計判断です。要件は「区別できること」までを求めています
- 先読みの量は実測で調整する設計候補です

### 人間判断待ち

- 未確定行の見せ方（記号、色、別欄など）について利用者の確認が望ましいです。誤って「壊れた行」と受け取られると、`LOG-026` の趣旨（解析エラーとして扱わない）が伝わりません

## 完了ゲート

- 実規模のログでスクロールとジャンプが成立する
- 保持上限、破棄、再取得が**内部状態で確認でき**、フロントエンドが保持する全行データ（表示ライブラリ内部の行モデル、DOM と購読が保持する行参照を含む）が上限を越えて増えない
- 原文と元の精度が失われない
- 未確定行、生表示、解析エラーが区別できる
