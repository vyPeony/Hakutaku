# P09 時系列統合表示

- 状態: 草案（Draft）
- 開始条件: P08 の完了ゲートを満たすこと。P05 の比較キーと P06 の索引が確定していること
- 前提フェーズ: P08
- 段階: 段階0（`VER-007` により時系列マージは段階0で確定してよい）
- 期待成果物: 複数ファイルのログを時刻順にマージした表示、ON/OFF の切り替え、同一比較キーの決定的な順序
- 予定変更範囲: コア側のマージクレート、GUI 側の統合表示と切り替え操作

## 目的

複数のログファイルを、ファイル横断で時系列順に把握しやすく表示します。

`VER-002` は段階0の確認対象に時系列統合表示を挙げています。`VER-007` により、時系列マージは段階0で確定してよい設計事項です。

## 表示順の例（`LOG-007`）

次の例では、表示順を `A-1 → A-2 → B-1 → A-3` とします。

| ログ | 日時 | 表示順 |
| --- | --- | ---: |
| A-1 | 2026/07/01 15:00:00.000 | 1 |
| A-2 | 2026/07/01 15:00:01.000 | 2 |
| B-1 | 2026/07/01 15:00:01.500 | 3 |
| A-3 | 2026/07/01 15:00:02.000 | 4 |

## 対象要件

| ID | 要求の要旨 |
| --- | --- |
| `LOG-006` | 複数のログファイルを同時に開ける |
| `LOG-007` | 複数ファイルのログを、ファイル横断で時系列順に把握しやすく表示できる |
| `LOG-008` | 時系列統合表示は常時強制せず、ユーザーが ON/OFF を切り替えられる |
| `LOG-015` | 統合表示が OFF の場合はファイル別タブで表示を切り替える。分割表示は不要 |
| `LOG-014` | 日時を持たない継続行は、統合表示でも直前の日時付き行と一体で表示する |
| `LOG-024` | 比較・マージにはミリ秒精度へ正規化した日時比較キーを使用する。元の精度と原文は保持する |
| `LOG-025` | 秒未満2桁は 1/100 秒として展開する（`.45` = 450 ミリ秒） |
| `LOG-012` | タイムゾーン表記のない日時は、同じ端末のローカル時刻として比較する |
| `LOG-016` | 時計がずれている場合も時刻補正を行わない |
| `PERF-008`／`PERF-010` | マージに必要な確保を予約経路へ通す |
| `VER-007` | 時系列マージは段階0で確定してよい |

## 作業項目

1. **個別索引のマージ。** 各ファイルを個別に解析・索引化し、その結果を時刻順にマージします。**統合結果全体の複製は可能な限り避けます**（4.2）。2 GB のログに対して統合結果を別途複製すると、予算 2 GB を即座に超えます。
2. **比較キーによる比較。** P05 で作ったミリ秒精度の比較キーを使います。欠落した秒・秒未満は 0 補完、秒未満2桁は 1/100 秒として展開済みの値を使います。
   - **時刻補正は行いません**（`LOG-016`）。複数端末やプロセスの時計がずれていても、記録された日時をそのまま使います
3. **同一キーの決定的な順序。** 比較キーが同一になった行は、**ファイルの表示順、次にファイル内の出現順**を使って決定的に並べます（4.2）。同じ入力と設定に対し、順序が毎回変化しないことが受け入れ条件です。

### 「ファイルの表示順」の定義（推奨案）

4.2 は「ファイルの表示順」を使うと定めていますが、その順序の決め方を定義していません。**定義しないと決定性が成立しません。** 次を推奨案として記録します。**確定には ADR または採用済み要件が必要です**（4.2 の暫定方針であるため）。

表示集合の世代ごとに不変な `source_ordinal` を各ソースへ割り当てます。

| ソースの追加経路 | `source_ordinal` の決め方 |
| --- | --- |
| 設定由来（`CFG-003`） | 設定に記載された順 |
| 同一操作でのアドホック複数選択 | 正規化した絶対パスを、**第1キーに ordinal case-insensitive、第2キーに ordinal（大文字・小文字を区別）** で並べてから追加 |
| 後から追加 | 既存の末尾へ追加 |
| ソース内 | ファイル内の出現順 |

この方式の利点は、**OS のファイル選択ダイアログが返す列挙順に依存しない**ことです。同じファイル群を選び直しても同じ順序になります。

**第2キーが必要な理由:** ordinal case-insensitive だけでは、大文字・小文字だけが異なるパスが同値になり、決定性を失います。Windows でも case-sensitive 属性のディレクトリでは `Log.txt` と `log.txt` が別ファイルとして共存し得ます。同値になった場合に ordinal（区別あり）で決着させます。

case-sensitive ディレクトリを対象外と明記する選択もありますが、`CFG-010` はローカル絶対パスを対象とするだけで、この区別を設けていません。**第2キーを置くほうが仕様に手を入れずに済みます。**

あわせて、**同じファイルが重複して選択された場合の扱い**を決めてください。パス文字列ではなくファイル識別子（file identity）で重複を除外すると、別名の同一ファイル（ハードリンクなど）も1件として扱えます。

将来タブの視覚的な並べ替えを提供する場合は、**明示的な並べ替え操作でのみ `source_ordinal` を更新し、表示集合の世代を進めます**。スクロールや再取得では変わりません。

**項目の安定した識別子（P04 の契約2）は `source_ordinal` に依存させません。** 依存させると、並べ替えで識別子が変わり、`PERF-012` の破棄・再取得が壊れます。
4. **継続行の一体表示。** 日時なし継続行を、統合表示でも直前の日時付き行と一体で表示します（`LOG-014`）。
5. **読み込み元の識別。** 統合された各行から、どのファイル由来かを識別できるようにします。
6. **ON/OFF の切り替え。** 統合表示を強制せず、切り替えられるようにします。OFF 時はファイル別タブへ戻ります（`LOG-015`）。
7. **再読み込みなしの切り替え。** 4.2 の暫定方針は「統合表示の ON/OFF、読み込み元による絞り込み、対象ファイルの追加・除外を再読み込みなしで行える構成を目指す」としています。索引を保持したまま切り替えられる設計にします。
8. **仮想スクロールとの統合。** 統合結果に対しても、P08 の範囲取得と保持上限が機能するようにします。統合結果を全件メモリへ展開しません。
   - **P04 で定めた範囲取得契約を変更しません。** 契約は「表示集合に対する範囲取得」として定義済みであり、表示集合がマージ結果になっても要求の形は変わりません。安定した識別子、読み込み元の来歴、再取得時の決定性、世代による無効化検出も P04・P06 で用意済みです
   - 契約の変更が必要になった場合、P04 の「契約に織り込む4点」のいずれかが不足していたことを意味します。黙って変えず、契約変更として扱ってください
9. **メモリ会計への接続。** マージに必要な確保を P02 の予約経路へ通します。

## 影響

- **セキュリティ:** 追加の影響はありません
- **データ:** 表示の切り替えで参照元を変更しません（`ERR-003`）
- **性能:** マージは全ファイルの索引を横断します。統合結果を複製しない設計が予算 2 GB を守るうえで重要です。**マージ結果の複製は最も起こしやすい予算超過の原因です**
- **互換性:** マージの順序規則は決定的である必要があります。後から変えると、同じログを見た2回の調査で行順が変わり、調査の再現性が失われます

## リスクと未決事項

### 確定要件に起因するもの

- **`LOG-016` により時刻補正を行わないため、端末間の時計ずれがそのまま表示順に現れます。** これは仕様どおりですが、利用者が「順序がおかしい」と受け取る可能性があります。読み込み元が識別できること（`LOG-007`）が唯一の手がかりです
- 同一比較キーの行順が「ファイルの表示順」に依存するため、**ファイルの表示順が変わると行順も変わります**。4.2 は「決定的に並べる」ことを求めており、同じ設定であれば再現します。表示順の定義（開いた順か、名前順か）を明確にする必要があります

### 暫定設計に起因するもの

- 「統合結果全体の複製を可能な限り避ける」は 4.2 の暫定方針です。実装方法は設計判断です
- 「対象ファイルの追加・除外を再読み込みなしで行える構成を目指す」は目標表現であり、達成できない場合に要件違反とはなりません

### 人間判断待ち

- **ファイルの表示順の定義が未決です。** 上記「『ファイルの表示順』の定義（推奨案）」に `source_ordinal` 方式を推奨案として記録しました。4.2 の暫定方針であるため、**ADR または採用済み要件として確定させる必要があります**

## 完了ゲート

- 2 ファイル以上の統合表示が日時昇順で成立し、順序が再現する
- 統合結果を複製せず、保持上限が機能する
- ON/OFF の切り替えがファイル別タブと往復できる
- 比較キーの正規化規則（`LOG-024`、`LOG-025`）が統合表示で確認できる
